
- 物理ファイルすべてに共通する情報（ファイルサイズなど）をファイル情報として管理します。
- ファイルタイプに応じた情報（画像の場合は幅、高さなど）を属性として管理します。
- サービス独自の付加情報はコンテンツの情報として管理します。

## データモデル

### GraphQL

```graphql
scalar Upload

type Content {
  id: ID!
  workspaceId: String!
  tags: [String!]!
  file: File!
  createdAt: String!
  updatedAt: String!
}

type File {
  path: String!
  name: String!
  extension: String!
  type: String
  size: Int!
}

type Mutation {
  registerContent(file: Upload!, workspaceId: String!, tags: [String!]!): Content!
  removeContent(id: ID!): Content!
}

type Query {
  fetchContent(id: ID!): Content
  downloadContent(id: ID!): Content
}
```

NOTE: 
コードブロックにgraphqlを指定してそのまま定義を設計する。今のところ*.graphqlsファイルからコードを生成し、ロジックだけを実装する想定。上記のスキーマ定義はgraphqlで扱うデータモデルやフィールドのrequire,optionalが含まれている。しかし入力バリデーションとロジックバリデーションは含まれていない。ユースケースに相当するものはミューテーションとクエリーになる想定。

## シーケンス

GraphQLが提供するAPIを利用してコンテンツの管理を行うシーケンスを以下に示します。

```mermaid
sequenceDiagram

participant user as User

box rgb(234 40 60) GraphQL
participant query as Query
participant mutation as Mutation
end

box rgb(105 158 202) MongoDB
participant collection-contents as Contents
end

user->>+query: fetchContent
query->>+collection-contents: find
collection-contents-->>-query: return
query-->>-user: feedback

user->>+query: downloadContent
query->>+collection-contents: find
collection-contents-->>-query: return
query-->>-user: feedback

user->>+mutation: addContent
mutation->>+collection-contents: insert
collection-contents-->>-mutation: return
mutation-->>-user: feedback

user->>+mutation: removeContent
mutation->>+collection-contents: delete
collection-contents-->>-mutation: return
mutation-->>-user: feedback
```
