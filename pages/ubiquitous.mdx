# ユビキタス言語

> 状態: 現行用語と合意済みの将来用語  
> 最終確認日: 2026-08-15

Memoriaの設計、実装、画面表示、Issue、PRで同じ意味を共有するための用語集です。現行実装名と将来設計名が異なる場合は、その対応を明記します。

## 記載方法

| 状態 | 意味 |
| --- | --- |
| 現行 | 現在の実装または承認済み仕様で使用する |
| 将来 | 合意済みだが、実装は完了していない |
| 旧称 | 新しい設計では使用せず、既存実装との対応にだけ使用する |
| 要レビュー | 初期設計に存在するが、詳細なルールは未確定 |

新しいプロダクト用語を導入するときは、対象設計と同じ変更でこのページを更新します。

## 主体

### User（ユーザー）

| 項目 | 内容 |
| --- | --- |
| 状態 | 現行 |
| 意味 | Memoriaのアプリケーションユーザー。認証サービスのsubjectと対応し、Communityへの参加やMediaの操作主体になる |
| 使用する表現 | User、ユーザー |
| 避ける表現 | 認証情報そのものをUserと呼ぶこと、すべての利用者をエンドユーザーと一括すること |

Userは現在ログイン中かどうかを表す状態ではありません。

### Community（コミュニティ）

| 項目 | 内容 |
| --- | --- |
| 状態 | 現行・将来設計を含む |
| 意味 | 家族、部活動、友人関係など、Mediaを内部で共有する閉じた独立空間 |
| 制約 | ネストしない。Community間で参加者、Media、権限を継承しない |

Userは複数Communityへ参加できます。同じUserが参加していても、Community同士に関係は生じません。

### Membership（参加関係）

| 項目 | 内容 |
| --- | --- |
| 状態 | 現行・詳細要レビュー |
| 意味 | UserがCommunityへ参加している関係 |
| 補足 | 参加・脱退・履歴は存在するが、招待やCommunity削除を含む詳細ライフサイクルは別途設計する |

### Community Member（コミュニティ参加者）

Communityへ参加しているUserです。Communityに公開されたMedia、またはCommunityが管理するMediaを閲覧できます。

### Community Administrator（コミュニティ管理者）

| 項目 | 内容 |
| --- | --- |
| 状態 | 現行・詳細要レビュー |
| 意味 | Communityの参加・管理情報を操作するUser |
| 現行実装との対応 | DBやコードに`owner`という識別子が残る場合がある |

MediaのCustodianと混同しないため、プロダクト設計ではCommunity Administratorまたはコミュニティ管理者を使用します。

## Media

### Media（メディア）

| 項目 | 内容 |
| --- | --- |
| 状態 | 将来 |
| 意味 | UserまたはCommunityが管理する静止画像・動画と、その付加情報 |
| 対象外 | Word、PDF、記事などの文書、音声単体、汎用ファイル |

現行実装との対応:

- 現行実装の`Image`は静止画像Mediaに相当します。
- 初期設計の`Content`は旧称です。新しい設計では`Media`を使用します。
- DB、GraphQL、コード識別子は移行が完了するまで`Image`などの現行名を保持できます。

### Image（静止画像）

| 項目 | 内容 |
| --- | --- |
| 状態 | 現行 |
| 意味 | 静止画像として扱うMedia。幅、高さなどの画像固有情報を持つ |
| 補足 | 現行実装ではMedia共通概念ではなく`Image`が中核モデルになっている |

### Video（動画）

| 項目 | 内容 |
| --- | --- |
| 状態 | 将来 |
| 意味 | 動画として扱うMedia。幅、高さ、再生時間、codec、frame rateなどの動画固有情報を持つ |

### Media Type（Media種別）

MediaがImageまたはVideoのどちらであるかを表します。ファイル拡張子だけでなく、検証済みのMIME typeやMedia情報と整合する必要があります。

## 管理・操作主体

### Uploader（アップロード実行者）

| 項目 | 内容 |
| --- | --- |
| 状態 | 将来 |
| 意味 | Mediaを最初にアップロードしたUser |
| 目的 | アップロード操作のトレース |
| 表さないもの | 著作権者、法的所有者、現在の管理主体 |

Mediaを委譲してもUploaderは変更しません。User削除後に不明になることを許容します。

### Custodian（管理主体）

| 項目 | 内容 |
| --- | --- |
| 状態 | 将来 |
| 意味 | Mediaを現在管理する、1 Userまたは1 Community |
| 制約 | Mediaごとに常に1つ存在し、UserとCommunityの共同管理や複数主体の共同管理を許可しない |
| 表さないもの | 著作権者、法的所有者 |

プロダクト設計ではMediaの管理主体を`Owner`と呼びません。Custodianであることと、Mediaを閲覧できることは別の概念です。

### Viewer（閲覧者）

| 項目 | 内容 |
| --- | --- |
| 状態 | 将来 |
| 意味 | Communityへの参加関係を通してMediaを閲覧できるUser |
| 補足 | Mediaの管理権限を持つことを意味しない |

## 公開と委譲

### Publish（公開）

Userが管理するMediaをCommunityの参加者全員から閲覧可能にする操作です。

- 公開してもCustodianはUserのままです。
- 1つのMediaを複数Communityへ公開できます。
- Communityは公開されたMediaの管理権限を取得しません。
- Community内の参加者別ACLは設けません。

「共有」は広い意味を持つため、アクセス関係を追加する具体的な操作には「公開」を使用します。

### Unpublish（公開解除）

Mediaと対象Communityの閲覧関係だけを解除する操作です。他Communityへの公開、Media本体、Custodianは変更しません。

### Transfer / Custodian Transfer（委譲）

MediaのCustodianを変更する操作です。

対応する遷移:

- UserからUser
- UserからCommunity
- CommunityからUser

委譲時は既存のCommunity公開をすべて解除します。Uploaderは変更しません。CommunityからCommunityへの直接委譲は、具体的なユースケースがないため提供しません。

### Media Community Access（Community公開関係）

| 項目 | 内容 |
| --- | --- |
| 状態 | 将来・現行に類似実装あり |
| 意味 | User管理MediaをCommunityの参加者が閲覧できる関係 |
| 補足 | Custodyではなく閲覧範囲を表す |

Communityが管理するMediaは、そのCommunity内部で閲覧できるため、別CommunityへのMedia Community Accessを持ちません。

## 分類

### Media Group（Mediaグループ）

| 項目 | 内容 |
| --- | --- |
| 状態 | 将来・Image Groupとして一部実装 |
| 意味 | Mediaを名称と親子関係で分類・整理する構造 |
| 構造 | 複数の親を許可する有向非巡回グラフ（DAG） |
| 影響しないもの | Custodian、公開範囲、閲覧権限、物理保存場所 |

1つのMediaは複数Media Groupへ所属できます。Groupから除外またはGroupを削除してもMedia本体は削除しません。

### Tag（タグ）

| 項目 | 内容 |
| --- | --- |
| 状態 | 現行 |
| 意味 | Mediaへ付与する短い属性または検索語 |
| Media Groupとの違い | 親子関係を持たない。分類構造ではなく検索・属性付与に使用する |

TagとMedia Groupは併用でき、どちらもアクセス制御には使用しません。

## トレース

### Media Event

| 項目 | 内容 |
| --- | --- |
| 状態 | 将来 |
| 意味 | Mediaに対して行われた重要操作のトレース情報 |
| 対象例 | UPLOADED、CUSTODIAN_CHANGED、ACCESS_CHANGED、DELETED |
| 表さないもの | 詳細なセキュリティ監査ログ、著作権の証明 |

actorとなったUserが削除された後に不明になることを許容します。保存期間は運用要件に基づいて決定し、永久保存を必須としません。

## 基本操作

### Upload（アップロード）

静止画像または動画のファイルをMemoriaへ登録し、Media、Uploader、アップロード日時、初期Custodianを確定する操作です。

### Register（登録）

新しいUser、Communityなどの情報をシステムへ追加する利用者操作です。DBの`INSERT`と同義ではありません。Mediaファイルの追加には、より具体的な「アップロード」を使用します。

### Edit（編集）

既存情報を利用者が変更し、保存する一連の操作です。技術的な`UPDATE`と同義ではありません。

### Delete（削除）

対象を利用できない状態にする利用者操作です。具体的な削除方式は対象のライフサイクル設計へ記載します。

Mediaについて「削除」と記載した場合は、現在の合意では物理ファイル、DBレコード、関連を削除し、復元できない操作を指します。ごみ箱、論理削除、問い合わせによる個別復元は提供しません。

## 使用しない、または意味を限定する用語

| 用語 | 方針 |
| --- | --- |
| Content | Mediaの旧称。現行識別子の説明以外では使用しない |
| Owner（Media） | 法的所有者やCommunity管理者と混同するため、Custodianを使用する |
| 著作権者 | システムで管理・証明しない |
| 共有 | 一般説明には使用できるが、具体的なアクセス操作には公開・公開解除を使用する |
| ACL（Community内部） | 参加者別のMedia閲覧制御は提供しない |
