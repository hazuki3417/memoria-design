# ADR 0002: ContentをMediaとして再定義する

- Status: Accepted
- Date: 2026-08-15

## Context

初期設計では管理対象を`Content`と呼んでいました。現在のシステムは静止画像を扱い、将来は動画へ対応する予定です。一方、Word、PDF、記事、音声単体などを扱う汎用ストレージサービスにはしません。

`Content`は対象範囲が広く、実際のプロダクト境界を正確に表しません。

## Decision

- 上位概念を`Media`とする
- Mediaの対象は静止画像と動画に限定する
- `Image`と`Video`をMediaの具体的な種類とする
- 初期設計のContent管理、委譲、公開、Groupの考え方をMediaへ引き継ぐ
- 著作権者と法的所有権をシステムで管理しない
- 現行のImage実装は直ちに変更せず、実装時に段階的な移行を設計する

## Alternatives

### Contentを維持する

別システムへの流用はしやすく見えますが、Memoriaの対象外である文書・記事まで含む誤解を生みます。具体的な別システム要件がないため採用しません。

### Assetを共通基盤とする

将来の再利用可能性はありますが、現時点では抽象化する具体的要件がありません。実際に共通性が確認できた段階で再検討します。

## Consequences

- プロダクト境界が画像・動画として明確になる
- ImageからMediaへのDB・GraphQL・コード移行が将来必要になる
- 初期設計資料のContent表記を読み替える必要がある
- 汎用ファイル対応を暗黙の要件として持たなくなる
