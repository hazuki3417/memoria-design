# 入力検証

> 状態: 現行方針

| 層 | 責務 |
| --- | --- |
| GraphQL | 型、必須、列挙値、scalar形式 |
| resolver・入力変換 | API固有の形式と正規化 |
| Service・domain | 業務ルールと認可 |
| Repository・DB | 一意性、参照整合性、競合 |
| Storage | size、media type、key境界 |

Web側の検証は利用者支援でありAPI側を省略する根拠にしません。業務ルールはservice・domainを正本とし、DB errorをそのまま利用者へ返しません。拡張子だけを信用せず、media typeと実データを検査します。MongoDB JSON Schemaを現行API全体の規約として扱いません。
