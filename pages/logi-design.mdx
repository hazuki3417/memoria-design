# 概要

ログ設計に関する情報を記載しています。


## ログレベル

ログレベルは、ログの重要度を示すためのもので、以下のようなものがあります。

| RFC 5424                 | Log4j/Logback | 出力先 | 説明                                         |
| :----------------------- | :------------ | :----: | :------------------------------------------- |
| 0 - Emergency (EMERG)    | FATAL         | stderr | 致命的なエラー。システムが使用できない状態。 |
| 1 - Alert (ALERT)        | FATAL         | stderr | すぐに対処が必要な状態。                     |
| 2 - Critical (CRIT)      | ERROR         | stderr | 重要なコンポーネントの障害。                 |
| 3 - Error (ERR)          | ERROR         | stderr | エラー状態。                                 |
| 4 - Warning (WARNING)    | WARN          | stderr | 警告状態。                                   |
| 5 - Notice (NOTICE)      | INFO          | stdout | 正常だが重要な状態。                         |
| 6 - Informational (INFO) | INFO          | stdout | 情報メッセージ。                             |
| 7 - Debug (DEBUG)        | DEBUG         | stdout | TRACE デバッグ情報。                         |

基本的には標準規格として定められたログレベルや、Log4j/Logback などのライブラリで使用されるログレベルの概念をそのまま利用します。


## ログフォーマット

JSONフォーマットを採用します。構造化ログを使用することで、ログの解析や可視化を容易にすることができるため。

## ログフィールド

以下のフィールドを含めます。

| フィールド     | 説明                               | 例                                 |
| :------------- | :--------------------------------- | ---------------------------------- |
| timestamp      | タイムスタンプ                     |                                    |
| log level      | ログレベル                         | `debug` `notice`                   |
| service name   | サービス名                         |                                    |
| container id   | コンテナ ID                        |                                    |
| correlation id | コレーション ID                    |                                    |
| message        | ログメッセージ                     |                                    |
| layer          | クリーンアーキテクチャのレイヤー層 | `presentation` `usecase` `service` |
| middleware     | ミドルウェア                       | `http` `app` `graphql` `database`  |
