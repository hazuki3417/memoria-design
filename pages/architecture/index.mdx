# リポジトリ構成

## 概要

Memoriaは4つの独立したGitリポジトリで構成する一つのプロダクトです。Git履歴とリリース単位は統合せず、設計、契約、Issue、PRで連携します。

| リポジトリ | 責務 | 所有する主な契約 |
| --- | --- | --- |
| `memoria-web` | Web UI、認証済み画面、GraphQLクライアント | UI挙動、operation、fragment |
| `memoria-api` | GraphQL API、ドメインロジック、永続化、ファイル入出力 | GraphQL schema、DB schema、storage contract |
| `memoria-design` | プロダクト設計、用語、横断的な意思決定 | 設計書、ADR、開発方針 |
| `memoria-IaC` | AWSリソースと実行環境 | runtime、network、IAM、storage resource |

## 責務境界

- WebはAPI契約を利用し、APIのビジネスルールを複製しない
- APIはドメインルールとデータアクセスを所有し、インフラの具体的な構築をIaCへ委ねる
- IaCは実行要件を実装するが、アプリケーション仕様を決定しない
- Designは意図と判断を記録するが、実行可能なschemaや設定を複製しない

## 契約変更

GraphQL、認証、ファイル保存、DB、実行環境の変更では、契約所有者を起点に影響を確認します。

- GraphQL schema: `memoria-api`
- Web operation・fragment: `memoria-web`
- PostgreSQL schema・query: `memoria-api`
- AWS resource・IAM: `memoria-IaC`
- プロダクト用語・横断設計: `memoria-design`

互換性を維持できない場合は、移行期間、PRの順序、deploy・migration・rollback方法を設計書へ記録します。
