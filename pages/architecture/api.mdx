# APIアーキテクチャ

## 目的

Memoria APIは、GraphQLを入口として、ドメインルール、PostgreSQLへの永続化、認証、S3互換オブジェクトストレージを提供します。実装の正本は`memoria-api`です。

## 依存方向

```text
GraphQL
  ↓
Service
  ↓
Repository interface
  ↓
Infrastructure / generated DB access
```

- GraphQL resolverは入出力の変換を担当し、ビジネスルールを持たない
- Serviceはユースケース、ドメインルール、transaction境界を担当する
- Repository interfaceは外部I/Oの境界を定義する
- PostgreSQL、認証、オブジェクトストレージの実装はinfrastructureへ置く
- ドメインとserviceからGraphQL、PostgreSQL、S3実装へ外向きに依存しない

## コード生成

| 契約 | 生成元 | 生成先 |
| --- | --- | --- |
| GraphQL | `memoria-api/schemas/graphql/` | `memoria-api/graph/` |
| SQL | `memoria-api/schemas/postgres/` | `memoria-api/internal/db/` |

生成元と生成物は同じPRに含め、生成できるファイルを直接編集しません。

## データアクセス

- PostgreSQLアクセスはpgxとsqlcを使用する
- 明示的な設計判断なしにORMを導入しない
- transactionは複数repository操作をまとめるservice・use case境界で管理する
- 認証済みcontextを認可判断の基準とし、クライアント指定IDを無条件に信頼しない
- storage操作ではユーザー・workspace境界を維持する

## テスト

- Service・ドメインルール: unit test
- Repository: DB integration test
- GraphQL: resolverまたはintegration test
- schema変更: 生成、build、Webクライアントへの影響確認
