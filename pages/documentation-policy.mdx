# ドキュメント管理方針

## 目的

Memoriaの情報を、設計の正本、実装に密着した手順、タスク固有の記録、AI contextに分けて管理します。同じ仕様を複数箇所へ複製せず、所有者と更新契機を明確にします。

## 現行実装と設計の関係

現在の挙動・構造を説明するときは、実行コードと実行可能なschemaを基準とします。ただし、実装に存在しない設計要素を自動的に削除または廃止しません。

設計と実装を照合した結果は、次の区分で管理します。

- **実装済み**: コードと実行可能な定義で確認できる
- **一部実装**: 契約または処理の一部だけ存在する
- **計画**: 設計済みだが実装では確認できない
- **実装差異**: 設計と異なる形で実装されている
- **要確認**: 意図や採否を資料だけでは判断できない

実装にない設計を廃止する場合、または実装を設計へ合わせる場合は、人間が判断します。調査時点の全体状況は[実装・設計整合状況](./implementation-status)に記録します。

## 配置基準

| 情報 | 正本 | 更新契機 |
| --- | --- | --- |
| プロダクト要求・用語 | `memoria-design` | 要求・用語の変更 |
| システム構成・責務境界 | `memoria-design` | アーキテクチャ変更 |
| 画面・API・DB・インフラ設計 | `memoria-design` | 設計判断の変更 |
| ADR | `memoria-design` | 長期的な意思決定 |
| GraphQL・SQL schema | 所有する実装リポジトリ | 契約・生成元の変更 |
| セットアップ・コマンド | 各実装リポジトリ | 実行方法の変更 |
| ディレクトリ構成・作業規則 | 各リポジトリの`AGENTS.md` | 作業境界の変更 |
| タスク要件・受け入れ条件 | Issue | タスクの合意 |
| 変更内容・検証結果 | PR | 変更の提出 |
| AI context | `memoria-design`のcontext map | 読み取り順序・参照先の変更 |

## 設計書

プロダクトまたは複数リポジトリに影響する設計は、このリポジトリを正本とします。実装リポジトリに設計内容を複製せず、正本へのリンクと、実装時に必要な最小限の補足だけを残します。

一方、次は実装リポジトリを正本とします。

- 実行可能なschema
- コード生成設定
- package・module設定
- 開発・検証コマンド
- ディレクトリ固有の実装規則
- ローカルでのみ必要なトラブルシューティング

設計書から実装リポジトリの契約を参照する場合、設計上の意味と実装上の事実を区別します。

## 設計書の形式

- 設計本文、判断、制約、状態はMDXを正本とする
- 概念図、ER図、状態遷移、シーケンスはMermaidを正本とする
- Mermaid図は目的別に小さく分割する
- 複雑な検討や自由なスケッチでdraw.ioを使用してもよい
- draw.ioで確定した内容はMDX＋Mermaidへ反映する
- 既存draw.ioは移行が完了するまで初期設計・参考資料として保持する
- draw.ioにしかない情報を確認せず削除しない
- 移行状況は[draw.io移行状況](./drawio-migration)で管理する

長期的な判断はADRへ、ドメインルールの詳細は対象設計書へ記録します。結論だけでなく、意図、制約、採用しなかった選択肢と理由も残します。

## 文書の状態

文書には必要に応じて次の状態を明示します。

- **現行**: 現在の合意または実装を説明する
- **提案**: 未承認の変更案
- **将来**: 合意済みだが未実装
- **廃止**: 使用しない情報。移行先を併記する

TODOを現在の仕様として扱いません。未決定事項には所有者または判断するIssueを関連付けます。

## 更新規則

- 実装変更と同時に、影響する正本と参照先を更新する
- 同じ説明をコピーせず、正本へリンクする
- リンク先のファイル移動では参照元を同じPRで更新する
- 横断変更ではリポジトリごとにPRを分け、相互リンクする
- プロダクト資料、README、Issue、PR本文は日本語を基本とする
- シークレット、本番識別子、個人情報を文書へ記載しない

## 不一致の扱い

資料と実装が一致しない場合は、自動的にどちらかを正しいものとして更新しません。

1. 差異と影響範囲を記録する
2. 現行仕様、実装不備、資料の更新漏れのどれかを人間が判断する
3. 正本と実装を必要な順序で更新する
4. 横断変更では関連PRと適用順序を記録する
