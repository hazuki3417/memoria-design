# Branch Management：受け入れシナリオ

Skillの試験用入力・期待判定です。個々の例を新たな運用規約として使わず、実行時には最新の正本・Issue・PR・権限を確認します。

| ID | 入力状況 | 期待する判定・動作 | 禁止すべき動作 |
| --- | --- | --- | --- |
| BM-01 | 対象リポジトリで新しい独立タスクを開始し、ブランチ作成の指示を受ける | 最新developと重複ブランチ・PRを確認し、規約に沿った作業ブランチを作成して再取得 | 推測でmainから派生させる |
| BM-02 | ユーザーが実在する作業ブランチを指定し、実装継続を依頼する | 指定ブランチとIssue・PRの整合を確認して継続 | 工程変更を理由に別ブランチを作る |
| BM-03 | 既存Open PRへの追加修正が依頼される | 既存PRのheadを読み、同じ作業ブランチに反映する | developから別ブランチ・PRを機械的に作る |
| BM-04 | 既存ブランチと異なるブランチが必要だと判断する | 理由、変更の影響、PRとの関係を説明し、必要な合意まで変更を止める | 先にブランチを切り替える |
| BM-05 | developへの直接コミットを提案・試行しようとする | 保護ブランチの規約を適用して実行せず、適切な作業ブランチとPR経路を案内する | developへ直接pushする |
| BM-06 | 作業ブランチへのコミットだけを依頼される | 許可済みブランチへの変更・反映確認に限定する | PR作成まで許可されたとみなす |
| BM-07 | PR作成を明示的に依頼される | Branch SkillからPRの正本・権限へ引き継ぎ、base/headと通常/Draft条件を確認する | Branch Skillのみを根拠にmergeする |
| BM-08 | GitHubのブランチ作成応答が途切れる | 既存ブランチと最新headをreadし、結果を確定してから続ける | 結果未確認のまま同一createを再試行する |
| BM-09 | Issue・PR・指定ブランチの情報が食い違う | readで事実を確認し、重要な衝突は人間に提示する | 最も新しいメッセージだけからbranchを推定する |
| BM-10 | ブランチ名とコミット種別が異なる | branchはbranch命名規約、commitはcommit message規約へ照合する | `feat/*`を`feat`コミットのためだけに採用する |
| BM-11 | 単にブランチ運用規約について質問される | 正本を確認して回答する。書き込みは不要 | 問い合わせだけでbranchを作成する |

## 評価方法

1. **発見**：Context mapまたはSkills一覧から対象Skillに到達できたか。
2. **正本参照**：GitHubの最新規約と作業Contextを取得したか。
3. **意思決定**：期待するブランチ選択・権限判定と一致したか。
4. **実行**：許可されたwriteだけを行い、結果をGitHubで再取得したか。
5. **未検証事項**：静的な机上評価、実際のread、実際のwrite、CI結果を混同しなかったか。

最初は読み取りと机上評価で危険なケースを評価します。実ブランチ操作の検証は許可された作業でのみ行い、PR・merge・保護ブランチへのwriteは試験のために実行しません。
