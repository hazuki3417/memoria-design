# Branch Management

## 目的と適用条件

Issueに基づく作業開始・再開、既存PRへの追加変更、作業ブランチの作成・切替・確認、コミット先の確定で使用します。単にブランチに関する質問へ回答する場合は、読み取りと説明のみ行います。

**このSkillを読むことは、ブランチ作成・コミット・PR作成の許可を意味しません。** ユーザーの依頼と既存規約が認める操作範囲を別途確定します。

リンク先は説明のコピーではありません。**適用時はGitHubで最新状態を読み取る**ものとし、このSkillを新たな運用規約にしません。参照先間の矛盾や重要な未合意事項があれば、操作せずユーザーへ報告します。

## 入力と確認事項

- ユーザーの最新の依頼、合意済みGoal・変更範囲、明示的な操作許可
- 対象リポジトリ、Issue番号、既存PRとhead/base、指定ブランチ（ある場合）
- 新規の独立した作業か、既存作業の継続か、結果不明の書き込みからの再開か

値を推測で埋めず、GitHubのreadで確認します。必要な情報を取得できない場合は、不確定なまま書き込みません。

## 実行手順

### 1. 最新の作業状態を確定する

1. 対象Issueと関連するOpen PR、既存ブランチ、最新のユーザー指示を照合する。
2. 既存PRの範囲内の継続、指定ブランチでの継続、新規の独立作業を区別する。
3. 書き込みの結果が不明な場合は、関連Issue・branch・commit・PRを先にreadし、同じwriteを重複実行しない。
4. 現在の依頼に含まれる権限を、ブランチ作成、ブランチへのコミット、PR作成、mergeで個別に区別する。

### 2. 対象ブランチを選択する

- **指定ブランチがある**：その実在と対象Task・PRとの整合性を確認し、原則そのブランチを使用する。
- **既存PR・作業ブランチに属する継続作業**：既存のheadを優先する。工程の変化だけでは新規ブランチを作らない。
- **新規の独立作業**：対象リポジトリの最新`develop`を起点として、規約に合う目的が分かる名前を選択する。緊急修正は正本の`hotfix`条件を確認する。
- **別ブランチへの変更が必要**：理由、影響、既存PRや検証結果との関係を説明し、必要な合意を得てから作成・切替する。
- **判断が確定しない**：候補と不足情報を提示し、GitHubの追加readまたは重要な判断の合意を得る。

ブランチ名の接頭辞、派生元、保護ブランチの扱いは必ずブランチ運用規約で確認します。コミット種別とブランチ接頭辞を混同しません。

### 3. 書き込み前後に検証する

書き込み直前に、対象リポジトリ、ブランチ名、派生元またはhead、対象Issue・PR、操作許可を照合します。許可のないPR作成や`main`・`develop`への直接pushは行いません。

許可範囲内の操作だけを実行し、直後にGitHubの最新状態を読み直して、作成・変更したブランチとコミット先を確認します。ツール応答が途切れた場合は同一writeを直ちに再試行せず、状態のreadを優先します。

### 4. 結果と継続条件を報告する

対象リポジトリ、使用したブランチ、派生元、実施した操作、実際にGitHubで確認した結果、未実施操作・未確認事項を伝えます。作業継続時にも同じブランチを再確認し、過去の会話だけで固定しません。

## 出力・完了条件

- 対象作業に使用すべきブランチと、その判断根拠が示されている。
- 実行したGitHub変更が、許可された操作と選択したブランチに一致している。
- GitHubから読み直して結果を確認している。確認できない場合は「未確認」として停止し、推測で完了扱いにしない。
- PR作成やmergeなど、今回許可されていない操作を追加で実行していない。
