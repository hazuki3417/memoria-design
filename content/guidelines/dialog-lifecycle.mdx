# Dialogのライフサイクルと開閉制御

## 基本原則

MemoriaのDialog / Modalは、呼び出し元の画面がマウントされている間、原則としてDialog Component自体をマウントした状態に保つ。ユーザー操作による開閉は、`opened` などの開閉状態を変更して制御する。

- `{opened && <Dialog ... />}` のように開く瞬間にDialog Componentを新規マウントし、閉じるときにアンマウントする実装を、通常の開閉方法として採用しない。
- 閉じた状態でDialogをレンダリングし、開く操作で`opened`を`true`、閉じる操作で`false`に変更する。
- Dialog Componentのマウント状態と、内部コンテンツの描画・データ取得・初期化のタイミングは分けて設計する。重いコンテンツや対象未選択時の詳細領域は条件付き描画してよい。
- 対象を切り替えるDialogでは、対象IDや選択状態をprops / stateで更新する。閉じるたびにDialog Componentを破棄して状態を初期化する方式には依存しない。入力値や一時状態をいつリセットするかは個別の画面仕様に従う。
- Dialogの開閉アニメーション、フォーカス制御、キーボード操作、オーバーレイ、Responsive Behaviorは既存の契約を維持する。アニメーションを揃えるためだけに独自トランジションを追加しない。
- 呼び出し元の画面自体がアンマウントされる場合や、明示的な例外要件がある場合はこの限りではない。例外は理由と影響を設計書に記録する。

## 本体とVisual Prototype

本体WebとVisual Prototypeは同じDialogライフサイクル方針を採用する。Prototypeの都合でマウント・アンマウント方式を変えて見た目や操作に差異を作らない。

## 既存実装への適用

MediaBrowserのImage Detailは、Modalを保持したまま`opened`で開閉する既存の方式を比較基準とする。GroupBrowserからのImage Detail起動も、閉じた状態から同じ方式で開く。

このガイドラインは今後の新規・変更実装に適用する。既存Dialog全件が準拠済みであることを意味しない。既存の不一致は調査し、visual / behavioral regressionを防ぎながら段階的に修正する。
