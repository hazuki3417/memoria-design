# 設定・シークレット


## 概要

> 実装状況: 各repositoryで環境変数を利用しています。secret管理と環境間の統一的な注入方式には差分があります。

設定は実行環境から注入し、変数名・必須条件・defaultは各実装リポジトリを正本とします。

- environmentとbranchを同一視しません。
- 必須値は起動時に検証します。
- secretをGit、Issue、PR、log、trace、container image、Client bundle、CDK output、設計書へ記載しません。
- GitHub ActionsからAWSへはOIDCと短期credentialを優先します。
- 非秘密設定とsecretを分離し、AWS上の具体的な保存serviceとpath規約はIaCが所有します。
- Webへ露出する環境変数は公開情報として扱います。
- S3、backup、認証設定に付与する権限は実行主体ごとに必要最小限とします。
- 詳細な保護対象とEC2運用への引き渡し条件は[Security・Privacy要求](./security-privacy-requirements)を参照します。

## 設定値の分類と注入

| 種類 | 決定時点 | 管理方法 |
| --- | --- | --- |
| Constant | build・source code | codeとversion管理 |
| Config | deploy・process起動 | 実行環境から注入 |
| 業務data | 実行時 | PostgreSQLなど所有domainの永続化 |
| Secret | 実行時・運用時 | 非公開の実行環境から最小権限で注入 |

process起動時に設定を読み込み、必須項目を検証し、型付きのConfigとして依存先へ渡します。各Layerでos.Getenvを直接繰り返し呼び出さず、secret値をerror、log、trace、Client bundleへ含めません。

secret storeの具体的なserviceは予算と運用要件に応じて選択し、高額な専用platformを初回Releaseの必須条件にしません。
