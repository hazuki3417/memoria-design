# 読み込み系の上限

一覧・検索・詳細取得について、利用者へ保証する取得件数・入力条件・表示状態を管理します。共通の分類・レビュー手順は[上限管理ポリシー](./index)に従います。個別の上限値は既存の設計を尊重し、未合意の値を追加しません。

## 一覧取得の上限（登録上限とは独立）

- Group一覧: default 30、maximum 100 / page（現行）
- Tag一覧: default 30、maximum 100 / page（現行）
- その他の読み込み上限は、上限到達時の表現も含めて[読み込み系のレビューIssue](https://github.com/hazuki3417/memoria-design/issues/341)で調査・判断する。未合意の値をこの設計の採用値とみなさない。

## 読み込み上限と表示のレビュー対象

読み込み処理では、利用者が一度に取得できる件数、追加取得できる条件、検索・詳細表示の範囲、制約を超えた場合の振る舞いを確認する。具体的な設計値と個別画面の表示仕様は、既存の[入力検証](/system/api/validation)、[非機能要件](/system/cross-cutting/non-functional-requirements)、[Collection Discovery](/design-system/patterns/collection-discovery)および各画面の仕様と照合して決定する。

| 確認する種類 | 対象と確認事項 |
| --- | --- |
| 一覧・接続 | 初期取得件数、最大ページサイズ、Cursor、終端、追加取得 |
| 単一・ネスト取得 | 詳細の関連情報、ネストの深さ、接続ごとのページング、同時に返す総量 |
| 検索・絞り込み | 検索文字列の長さ、フィルタ条件数・ID数、条件超過時の振る舞い |
| API利用上の制約 | 利用者に適用されるアクセス頻度・同時取得・取得可能な情報量などの制約と超過時の応答 |
| 一覧の状態 | 正常0件、次ページあり、終端、追加取得中、追加取得失敗 |
| 制約による拒否 | ページサイズ超過、検索条件過多、選択・保持の上限到達、Rate limit超過 |
| 障害との区別 | Timeout、通信障害、認可失敗、取得失敗を上限到達と区別できるか |
| UIの表現 | 操作の無効化、説明、再試行、表示済みデータ・選択・スクロールの維持、Accessibility |

DBの取得方法、SQLの最適化、Cache、N+1対策などの実装方法はこの設計の対象に含めない。必要な改善は対応する実装Issueで扱い、アプリケーション仕様を実装都合から逆算しない。

この表は**レビュー観点の定義**であり、未決定の上限値・新しいAPIエラー種別・画面表示を一律に決めるものではない。上限の種類と利用者へ保証する振る舞いを分離して確認し、Domain・API・画面・Design Systemの各正本で必要な仕様を決める。


## 読み込み系マトリクス

| ID | 対象・操作 | 種別・適用単位 | 設計値 |
| --- | --- | --- | --- |
| LIM-021 | Group一覧ページング | 取得 / API request | 既定30、最大100 |
| LIM-022 | Tag一覧ページング | 取得 / API request | 既定30、最大100 |

既存IDを保持し、ほかの読み込み項目は[Issue #341](https://github.com/hazuki3417/memoria-design/issues/341)でのレビューと合意後に追加します。正常な一覧終端と上限違反による拒否、障害時の取得失敗は区別します。具体的な画面状態は[Collection Discovery](/design-system/patterns/collection-discovery)および対象の画面設計を正本とします。
