# 書き込み系の上限

利用者に保証する保持件数・容量・操作単位・同時転送・構造上限と、上限到達時の振る舞いを定義します。内部の検査場所、Transaction、SQLや処理負荷対策は実装方式として扱い、上限値を実装都合から決めません。共通の分類・レビュー手順は[上限管理ポリシー](./index)に従います。

## 保持上限

| 対象 | 採用値 | 適用スコープ |
| --- | --- | --- |
| Media件数 | アプリ独自の件数上限なし | Scope |
| Media Original容量 | 5,000,000,000 bytes | アップロード対象Scope |
| Tagカタログ件数 | アプリ独自の件数上限なし | Scope |
| Group件数 | 1,000件 | Personal / Communityの各Scope |
| Community作成数 | 100件 | Userが作成したCommunity |
| Community参加数 | 100件 | Userが参加中のCommunity |
| Community参加者数 | 30人 | Community |
| Community管理者数 | 3人 | Community |
| Mediaに紐づくTag数 | 30件 | Media × Scopeの更新後状態 |
| Groupの直接親数・直接子数 | それぞれ10件 | Group |
| Group階層深さ | 最大20 | ScopeのGroup DAG |

Community作成数は所有・作成したCommunityを対象とし、参加数とは独立に計測する。削除済みCommunityを作成数に含めるか、作成者と所有者のどちらを数えるかは未決定であり、確定した仕様と区別する。参加者数には管理者を含む。Communityへの参加経路と作成者の初期参加も上限強制の対象とする。

## 1操作・1回の要求で扱える件数の上限

| 操作 | 採用値 | 備考 |
| --- | --- | --- |
| Media Uploadのファイル選択 | 100ファイル | 1回のアップロード操作で扱えるファイル数 |
| Media Upload同時転送 | 3ファイル | アップロード操作中に同時転送する数 |
| Media Upload原本サイズ | 128 MiB / ファイル | 利用者がアップロードできる原本のサイズ |
| Media Tag状態更新 | 更新後30 Tag | 1 Media × Scope、既存契約 |
| Media一括Tag変更 | 100 Media / 操作 | 一括変更操作が提供される場合に適用。現時点での提供は意味しない |
| 1 GroupへのMedia一括分類（追加・削除） | 100 Media / 1回の要求 | 1回の要求で対象にできるMedia数 |
| 複数GroupへのMedia分類 | 100 Media、10 Group、組み合わせ最大1,000 / 1回の要求 | 1回の要求で指定できる対象と組み合わせ数 |
| Group作成/更新 | 1 Group / 1回の要求 | 1回の要求で扱うGroup数 |
| Group親子関係編集 | 最終状態で親・子各10件 | 変更後も直接の親・子の各上限を超えない |
| Community作成 | 1 Community / 1回の要求 | 1回の要求で作成するCommunity数 |
| Communityメンバーの追加・除外・役割変更 | 1人 / 1回の要求 | 未提供の操作がある場合は、提供を決定した時点で適用 |

## 上限到達時に保証する振る舞い

- 利用者が上限を超える操作を試みた場合、超過した制約と適用対象を理解できるように案内する。具体的な画面の表示方法・文言は対応する画面設計とDesign Systemで定める。
- 1回の操作に指定できる件数が上限を超えた場合、その操作による変更は開始しない。上限以内の別操作や対象数の調整を妨げない。
- 保持件数・容量などの上限は、同時に操作しても利用者に保証する上限を超えない。
- 既存のMedia Uploadにおけるファイル単位の結果、Group分類におけるMedia単位の結果など、上限違反以外に対する部分成功の振る舞いは維持する。
- 上限到達と通信障害・権限不足・競合などを区別し、利用者が次に取れる操作を分かるようにする。
