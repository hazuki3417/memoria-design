# 認証・認可・Privacy共通方針

## 概要

User、Community、Mediaに共通する認証、操作主体、認可の再評価、個人情報、秘密情報の取り扱いを定義します。各domainでは、そのdomain固有のrole、権限表、例外だけを定義します。保護対象、脅威、metadata、Storage、log、残存riskは[Security・Privacy要求](./security-privacy-requirements)を正本とします。

## 認証と操作主体

- 認証はAuth0、Product内のUser解決と認可はMemoriaが担当する。
- Auth0のissuerとsubjectの組で内部Userを一意に解決する。
- BrowserはNext.jsのHttpOnly session Cookieを使用し、Next.jsからAPIへAuth0 Access Tokenを渡すBFF寄りの構成を基本とする。
- APIはAccess Tokenの署名、issuer、audience、有効期限を検証する。
- ID TokenをAPIのAuthorizationに使用せず、tokenをURLや公開stateへ保存しない。
- ACTIVE Userだけが操作でき、未登録・DELETING Userは拒否する。
- 内部User IDと外部認証identifierを公開用識別子として扱わない。

## 認可の評価

- 認可は操作対象、現在のUser状態、Membership、Administrator、Custody、Uploaderに基づいて評価する。
- 画面表示、事前取得した権限、古いtoken claimだけを認可根拠にしない。
- 更新・削除など競合する操作では、対象lock取得後に存在、状態、権限を再確認する。
- 退会、除外、account削除、session失効後は新しい閲覧許可や操作権限を発行しない。
- 対象外UserへCommunityやMediaの内部情報を返さない。

## 非公開リソースの公開エラー契約

- **合意済み**: 現在のUserが閲覧できないCommunity・Media等の非公開リソースは、存在の有無を公開せず404相当を返す。存在しないリソースと、閲覧権限のないリソースの違いを公開応答から推測させない。
- **合意済み**: 現在のUserが閲覧できるリソースに対して、管理・Original downloadなど許可されない操作を要求した場合は403相当を返す。
- 認証されていない場合は認証エラーを優先し、403・404と混同しない。権限は操作時点のUser状態・Membership・Custody・Uploaderで再評価する。
- APIのGraphQL公開エラーコード、HTTP Status、複数Field Error時の扱いはAPI契約で具体化する。Webは公開エラーを独自変換せず、存在確認のための追加問い合わせをしない。

## 個人情報の最小化

- email、氏名、電話番号、住所、生年月日、profile画像をProductに保存しない。
- Auth0表示名は、User登録時のnickname初期値としてだけ利用する。
- 削除済みUserのnickname、email、認証identifierを、他dataを保持する目的で退避しない。
- nicknameを表示する範囲は、参加者一覧、申請者確認など許可されたユースケースに限定する。
- Originalは変更せず保存し、表示用VariantからEXIF、GPS、撮影日時、端末情報を除去する。
- 画像metadataを業務dataとして抽出・保存・表示しない。

## 秘密情報とURL

- password、credential、認証token、招待token、署名付きURL、不要な個人情報をlogへ出力しない。
- Login・登録後のreturn URLは許可された内部URLだけを受け付ける。
- 招待URLと署名付き配信URLには、用途に応じた失効条件と有効期限を設定する。
- 招待tokenは推測困難な乱数とし、平文ではなくhashだけを保存する。
- Cookieは認証方式に応じてHttpOnly、Secure、適切なSameSiteを設定し、必要なCSRF対策を行う。
- 入力検証は[入力検証](/system/api/validation)、logの保持と保護は[ログ・可観測性](./observability)を正本とする。

## Domain固有の規則

- User登録、再認証、sessionは[Userの認証と認可](/user/authentication-authorization)。
- Administrator、Member、Uploaderの権限は[Community権限](/community/authorization)。
- Custody、共有、Original downloadは[Mediaユースケース](/media/use-cases)。
