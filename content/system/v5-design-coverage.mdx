## 合意済みoverrideの要点

- Community roleは`member | admin`を維持する。
- Invitation acceptは直接Membershipを成立させ、Join Requestは独立した将来機能として維持する。
- Media本体へUser/Community ownership IDを持たせず`media_custodies`で管理関係を分離する。
- Media Community Access / Media Event / Custody Transfer等の将来設計は、Initial ReleaseでUI/API提供しなくても論理設計として維持する。
- Media Group DAGを維持し、Group scopeはGroup自身が持つ。
- ProcessingJob / Image / ImageVariant / atomic publicationはv5を取り込む。
- User lifecycle / account deletionはGitHub現行を維持しInitial Release対象とする。保持MediaのUploader FKはUser削除後NULL化しPII snapshotを保持しない。
- ULID=`varchar(26)`等、既に確定済みのPersistence共通規約を未決定へ戻さない。

## 照合結果

全26 Current Override、全58 Cross-cutting、全55 Application/Domain項目（59–113）にGitHub上の着地点を割り当てました。単なる項目一覧ではなく、A/B/C/Dと正本pathを追跡できる状態を完成条件とします。

`Initial Release外`は設計削除理由にしません。将来機能を見越したDomain/Persistence構造は維持し、Release Scopeと分離します。
