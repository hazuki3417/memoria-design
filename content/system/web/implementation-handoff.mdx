# Web実装引き渡し

## 境界

Webは画面・interaction・navigationを所有し、Product authorizationやbusiness invariantの正本にはしません。Server stateはApollo、editable draftはReact Hook Form、navigation / shareable filterはURL、local presentation stateはReact local stateを基本とします。

## BFF / authentication

BrowserはHttpOnly sessionを使用し、Next.js BFFがAPI向けAccess Tokenを取得してmemoria-apiへ転送します。BrowserへAccess Token、Auth0 refresh token、account deletion reauthentication proofを保存しません。

Invitation deep linkとAccount deletion callbackのreturn pathはallowlistされた内部pathだけを受け付けます。外部URLや任意redirectを許可しません。

Account deletionはReview作成後にBFFがAuth0 `prompt=login` + `max_age=0` を開始し、callback成功時に対象reviewTokenと現在認証主体をAPI内部binding境界へ登録します。callbackだけで削除Mutationを実行せず、Final Confirmationへ戻してUserの明示操作を待ちます。

## GraphQL operation

Schema fieldを画面名へ複製せず、Web側で画面 / user goalごとのnamed operationとfragmentを定義します。generated typeを使用し、response型を手書き複製しません。

Connection paginationは親resource IDと全filter / sort / scope引数をcache keyへ反映します。PersonalとCommunity、異なるCommunity、異なるfilterのedgeを混在させません。

Mutation後に一覧構成が変わる場合、初期実装は影響Connectionのrefetch / invalidationを優先します。複雑なmanual edge surgeryはUX上必要と確認された場合だけ導入します。

## Media upload

複数file選択はfileごとに `POST /api/media/uploads` を実行し、各fileに独立idempotencyKeyを割り当てます。通信結果不明のretryは同じkey、Userが新たに開始したuploadは新しいkeyを使用します。

upload成功後は受付MediaをPROCESSINGとして扱い、Variant完成をupload request内で待ちません。Media statusはGraphQLから再取得します。fileごとの成功 / 失敗を独立表示し、1件失敗で成功済みMediaをrollbackしません。

## Immediate-save settings

Preference / Accentの連続変更は同一resourceのrequestを直列化し、保存中の変更をcoalesceして最新値を次requestへ送ります。古いresponseで新しいlocal intentを上書きしません。APIへclient sequenceを追加しません。

## Error handling

GraphQLとUpload HTTPのstable Application error codeを共通分類へmappingします。認証切れ、forbidden、validation、conflict、not-found、retryable infrastructureをUI上で区別します。raw GraphQL error messageやHTTP statusだけでbusiness分岐しません。

CONFLICTでserver stateが変化している操作は再取得してUserへ再確認させ、破壊的操作を自動retryしません。network failureでidempotent commandの結果が不明な場合だけ同じidempotency keyで安全にretryできます。

## Responsive / prototype contract

実装置換・Component化でも確定済みScreen Specification / Design Prototypeの表示情報、layout、interaction、state、responsive behaviorを不変条件とします。共通Component都合で既存consumer固有Capabilityを削除しません。

## Test handoff

Operation validation / codegen、Apollo cache partition、pagination、mutation後refetch、deep-link return、reauth callback、multi-file upload partial failure、immediate-save orderingをWeb integration test対象とします。Prototypeから本体実装へ移す際はvisual / behavioral regressionも確認します。
