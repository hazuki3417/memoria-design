# Usage：テストマトリクス

## 概要・適用範囲

本書はPersonal UsageとCommunity Usageの確定済み仕様から、集計Scope、容量・形式別内訳、表示単位、取得状態・復旧、Navigation・認可、Responsive・Accessibilityを検証条件へ展開する。設計の期待結果は参照元を正本とし、本書では製品仕様を追加決定しない。現行実装・Storyの有無やテスト実行成功を示す資料ではない。

Usageを含む全画面のUpload制約表示・Upload拒否条件の詳細、DB計算方式、GraphQL field構造、Component構成および視覚レイアウトの未採用詳細は本書で固定しない。Backendに属するOriginal計上・format確定の検証も、Frontendの表示テストと区別して対象に含める。

## マトリクスの記述規則

各行のGiven / When / Thenは前提／操作・イベント／外から観測できる結果を示す。階層は **Unit**=純粋計算、**C**=Component、**I**=Frontend Integration（GraphQL境界Mock）、**BE**=Backend・Domain・DBの契約検証、**E2E**=実Frontend・API・Test DBを用いる主要Flowを表す。階層の複数候補は全階層での一律重複を義務づけない。**P0** は集計・scope・状態・権限の欠陥影響が大きい主要保証、**P1** は補完的な表示・操作保証とする。優先度は実装完了状態を表さない。

**設計状態**: 記載した条件は参照先の確定仕様またはその直接的なテスト分解である。**実装・実行状態**: 本書では網羅的な実装・実行結果を管理していない。設計済み・実装済み・成功を混同せず、最新状態は各Repositoryの実装・CIで確認する。UI表現に関する未採用事項は下記に分ける。

## Fixture・依存境界

- User Custodian Original、Community A/B Custodian Original、Personal OriginalのCommunity共有、登録未確定Upload、Variant、中間ファイル、Variant処理失敗を独立したデータとして準備する。
- 上限は各scope独立に5,000,000,000 bytes。0、通常量、ちょうど上限と、Decimal / Binaryで換算差が分かるbyte値を使用する。集計値は丸め済みLabelから逆算せず正本のbyte数と件数で検証する。
- JPEG (.jpg/.jpeg)、PNG、WebP、HEIC/HEIF (.heic/.heif)と、申告MIME・拡張子が確定canonical formatと異なる例を用意する。検証済みcanonical formatが分類根拠である。
- Loadingは応答保留、Error→成功とError→再失敗は制御された外部応答で再現する。Frontend Integrationでは生成済みGraphQL Hook・Apollo Clientを通し、外部GraphQL応答をMockする。Backendの集計・認可・永続化はFrontend Mockだけで保証済みとしない。
- Active Administrator / Member / Membership失効を分離する。Visual StateとViewportの撮影条件は安定化し、VRT Baselineは承認前に確定扱いしない。

## VRT候補とViewport

視覚的に区別する価値のある状態のみを選び、全Case × 全Viewportの直積は要求しない。

| Visual State | 主な観測内容 | Viewport候補 | 選定理由 |
| --- | --- | --- | --- |
| Ready（形式別内訳あり） | 容量モードの上限、件数、3列内訳と共通切替の理解 | Desktop 1440px / Mobile 375px | 情報密度・Responsive差分 |
| 割合モード | Storageと内訳の連動、容量上限の固定表示、見出し「使用量」の維持と表下の補足なし | Desktop / Mobile | 切替による情報喪失・操作の誤認防止 |
| Empty（確定0件） | 実値0と説明の視認性 | Desktop / Mobile | Loadingとの視覚的区別 |
| Loading | 未確定値の隠蔽、既知の画面構造維持 | Desktop / Mobile | 幅ごとのPlaceholder表示 |
| Error / Retry | 説明、Action、Focus可能性 | Desktop / Mobile | 復帰Actionの欠落防止 |
| Limit reached | 使用量と上限到達の理解 | Desktop / Mobile | 重要な境界状態 |
| Community Ready | Community scopeの表示・Navigation | Desktop / Mobile | Personalと異なるConsumer境界 |

上記はVRT候補であり、撮影の必要性・重複削減・具体的な採用UIのBaselineはVisual Reviewで確定する。現段階でStoryへの`vrt`タグ付与やBaseline採用を要求しない。Medium幅のCapabilityはUI-01で検証し、独立VRTは幅固有の視覚リスクが確認された場合に選ぶ。Light / Darkは意味・Contrastの検証を行い、別Baselineの必要性を視覚リスクで判断する。

## 未決定事項と検証範囲

- 画面詳細仕様と画面UI設計で確定した3列構造・0件時の4形式・Loadingフッター・表示切替とソートの連動・初期使用量降順・Storage Barの表示順はUI-06〜12で検証する。特定のSkeleton寸法や固定色、実装固有のDOM構造など、画面仕様が定めない詳細は本書で固定しない。
- Personal Usageの独立Destination化については既存の設計PR [#224](https://github.com/hazuki3417/memoria-design/pull/224) が存在する。現在の`develop`にあるSettings配下の仕様を本書の基準とし、変更が統合された際にNavigation関連ケースと参照を再照合する。PR本文のみを根拠に未統合仕様を確定しない。
- APIの具体Operation・Error型、集計更新タイミングと実際の見た目は各所有正本で判断する。本書のFixtureから仕様を追加決定しない。

## 実装との対応・課題

現行Web・APIのテストコードとの全件照合は本書では実施していない。後続の実装時にCase ID単位でCoverage、未実装、未実行、成功・失敗を追跡し、差異は実装の追随か設計変更の必要性を区別する。既存UIの視覚・動作・Responsive契約は合意のない変更をしない。

## テスト設計の完了基準

Scopeと計上・除外、容量と分類整合、Preferences単位、状態・復帰、認可・Navigation、Responsive・Accessibilityの主要期待結果を仕様に追跡でき、Given / When / Then、候補階層、再現Fixture・依存境界、未決定事項が区別されていること。**実装・Story追加・CI実行・VRT Baseline承認は別工程**であり、本書の追加だけで完了したとしない。
