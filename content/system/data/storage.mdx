# Mediaストレージ

## 概要

> 実装状況: S3互換storageによるImage保存は存在しますが、Media共通path、幅別Variant、Private Variantの署名URL配信には差分があります。

DBはMediaの属性・管理主体・公開関係、Object Storageは原本と派生fileを保持します。

## Path

```text
media/{mediaId}/original/source.{extension}
media/{mediaId}/variants/{jobId}/{width}.webp
downloads/{downloadRequestId}.zip
```

- `original/source.{extension}`は変更していない原本です。
- `variants/{jobId}/{width}.webp`はアスペクト比を維持した幅別の表示用画像です。Job固有keyへ完全な集合を生成し、公開状態はObject pathではなくDBの`image_variants.storage_key`を正本とします。
- 一覧と詳細表示は同じVariant集合を使用し、thumbnail用とpreview用のfileは分けません。
- User IDやCommunity IDをpathへ含めず、管理委譲でObjectを移動しません。
- watermark付きfileは要求がないため生成しません。
- 動画の再生用派生物は形式・変換方式の合意後にMedia配下へ追加します。

## Uploadとdownload

初期のupload経路は`Frontend → API → Object Storage`です。APIがfile size、MIME type、実dataを検証し、Originalを最終keyへ保存します。署名付きURLをFrontendへ渡す直接uploadは、通信量やAPIの負荷が問題になった場合の将来的な最適化候補とし、現在の標準経路には含めません。

単一downloadは認可後にOriginalの期限付きURLを返します。User管理MediaではUser Custodianだけがdownloadでき、Community管理MediaではCommunity Administratorと、Communityへ参加中の対象Uploader本人がdownloadできます。その他のCommunity Memberへの公開はVariantの閲覧だけを許可します。複数downloadを提供する場合は認可済みOriginalだけをzip化して`downloads`へ配置し、期限付きURLを返します。zipはObject Storageのlifecycleで自動削除します。

## Private配信

S3 bucketはprivateとし、public access blockと保存時暗号化を適用します。**Initial Releaseの表示用VariantはS3互換Object StorageのSigV4 Presigned GET URLを採用し、CloudFrontは配信経路から除外します（2026-10-26変更合意）。** APIが現在のPersonal / Communityの閲覧権限を検証してから、公開済み `image_variants.storage_key` に対し15分有効の署名付きURLを発行します。Clientは署名URLをそのまま `srcset` / `sizes` で使用し、bucket名やkeyを組み立てません。Original downloadは別の認可・5分期限です。

S3アクセスはServer-sideの内部Endpointと、BrowserからHTTPSで到達可能な配信Endpointを分離します。署名はBrowserからリクエストする実際の配信Host・pathを対象とし、内部Hostを署名してからURLだけ置換しません。配信EndpointはPrivate ObjectへのSigV4検証付きGETをサポートする必要があり、bucket公開を前提にしません。Public Endpointの未設定・署名鍵の欠落時は無署名URLへfallbackしないで失敗させます。開発時のlocalhost HTTPは明示的な開発環境だけ許容し、本番はHTTPS必須とします。

APIの署名付きURL・署名情報をlog / traceへ記録しません。権限喪失後は新しいURLを発行しませんが、発行済みURLは15分間まで有効となる残存riskを許容します。

Webはbucket名や恒久keyへ依存しません。APIは認可とkey生成、IaCはbucket、IAM、暗号化、lifecycleを所有します。upload時にsize、MIME type、実dataを検査します。詳細は[Media処理と派生物](/media/processing)と[CommunityとMediaの公開](/media/community-access)を参照してください。

## 容量、署名期限、保持

画像Originalの上限、総容量の設計目安、Original downloadと表示用配信の署名期限、一時archiveの保持、backupと物理削除の関係は[非機能要件](/system/cross-cutting/non-functional-requirements)を正本とします。動画固有の上限は動画処理の詳細設計で決定し、画像用の数値を流用しません。
