# Data Implementation Open Items

## 目的

共有済み資料およびGitHub正本に具体的な決定が存在しないPostgreSQL / Persistence実装詳細を記録します。ここに記載された事項は既設計の欠落ではなく、今後設計を詰める対象です。

横断追跡Issue: [#61 design: resolve remaining implementation details](https://github.com/hazuki3417/memoria-design/issues/61)

本ページは#61のうちData / Persistence領域だけを扱います。GraphQL、Frontend、Worker、Infrastructure等の未決定事項は#61と各主Issueを参照します。

## 未決定事項

| 項目 | 現在確定している境界 | 今後決定する内容 |
| --- | --- | --- |
| Final DDL | 論理relation、共通型、主要constraint方針 | 全column、constraint name、未指定FK action、index、migration SQL |
| Tag normalization | `name`と`normalized_name`を分離しscope内uniquenessを保証 | Unicode normalization、case folding、空白処理、locale policy |
| Processing publication | `image_variants`の既存published集合を維持したまま別storage keyへ生成し、Media lock下の短いTransactionで全Variantを一括更新 | final SQL / Repository実装 |
| Outbox schema | `event_type + event_version`、versioned envelope、PUBLISHED 7日保持、PostgreSQL truth、Redis Streams delivery | payloadのevent種別ごとの具体schema / serialization実装 |
| Idempotency persistence | actor + operation + keyを一意化しrequest hashを検証、保証期間24時間、responseは最小識別情報 | cleanup interval、operation別response snapshot、payload size limit |
| Upload quota reservation | concurrent uploadの超過をreservationで防止 | reservation tableのfinal column、expiry、cleanup query、lock SQL |
| Migration compatibility | gooseによるversioned SQL migrationをschema変更履歴の正本とし、`schema.sql`は生成snapshotとする | 変更ごとのrollout/rollback SQL、必要な場合のexpand/migrate/contract手順 |
| HA-aware DB client | PostgreSQL HAをproduction baselineとする | failover endpoint確定後のconnection / retry / migration execution detail |

## 更新ルール

決定した項目は対応する正本へ反映し、本ページから削除または「決定済み」として参照先を記載します。重要な技術選定はADR、実装単位で独立して追跡すべきものはGitHub Issueとします。

#61のData / Persistence項目を解消する条件は、上記項目について明示的な設計判断が行われ、対応する正本とImplementation Detailed Design traceabilityが更新されていることです。
