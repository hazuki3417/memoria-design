# インフラストラクチャ設計

## 目的

Memoriaは、AWS上でContainer化したApplicationとself-hosted PostgreSQL / Redisを運用します。Production相当構成では単一Host同居を可用性Baselineとせず、Application、PostgreSQL HA、Redis Sentinel HAのfailure domainを分離します。

設計優先順位はCorrectness、Simplicity、Explicitness、Observability、必要性が観測された後のOptimizationの順です。

## Production baseline

- Application / API / Worker / Outbox PublisherはDocker container / processとして分離可能な構成にします。
- PostgreSQLはPrimary 1 + Standby 1以上を基本とし、Streaming Replicationを利用します。初期候補はasync replicationです。
- Primary / Standbyは別Host / 別failure domainへ配置し、Productionでは可能なら別AZとします。
- Applicationは個別DB Hostへ固定依存せず、DB endpoint / routingを介してcurrent Primaryへ接続できる構成にします。
- Redisは1 Primary + 2 Replicas、Sentinel x3、quorum 2をBaselineとし、ApplicationはSentinel-aware clientを使用します。
- Redis Clusterは初期リリースでは採用しません。Sharding requirementが具体化した場合に再検討します。
- RDS / ElastiCacheを現時点のBaselineとはせず、EC2 / EBS / S3 / IAM / Security Group / SSM等を中心としたself-host方針を維持します。

具体的なEC2台数、Application node配置、PostgreSQL HA manager / proxy、automatic failover方式はImplementation Detailed Designで確定します。

## Availability / Recovery

ReplicationとBackupは別責務です。

```text
Replication = Availability
Backup      = Recovery
```

PostgreSQLはperiodic/base backup + WAL archive + Object Storage + restore testを基本方向とし、必要なRPOに応じてPITRを利用します。RedisはAOF / EBSを利用可能ですがApplication Truthではなく、Redis Streams loss時はPostgreSQL Outbox / ProcessingJob stateからreconciliationして再配送します。

## Development / Production parity

DevelopmentでもProductionと同じsoftware topology、version、image、health check、基本configuration templateを利用します。ただしDevelopment用ComposeをそのままProductionへ配備することはしません。

```text
Normal Development
→ Docker Compose: Single PostgreSQL / Single Redisを許容

HA Validation
→ Docker Compose HA profile: PostgreSQL HA + Redis Data x3 + Sentinel x3

Production
→ EC2 + Docker + EBS + multi-host / multi-AZ + production secrets / monitoring / backup
```

Local Docker HAはsoftware-level failover / reconnect / electionの検証用であり、Host / AZ failureを再現するInfrastructure-level HAとは区別します。

## Observability

PostgreSQLではPrimary/Standby availability、replication lag、WAL、disk、connection、CPU/memory、checkpoint、backup、restore test、failover stateを監視対象とします。RedisではPrimary/Replica/Sentinel availability、replication/failover、Streams、AOF/disk等を観測可能にします。具体的thresholdは運用要件と実測に基づいて決めます。
