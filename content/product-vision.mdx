# プロダクトビジョン・設計原則

## 目的

Memoriaは、家族やサークルなど、現実のCommunityで生まれた写真や動画を、その集まりの人たちが一緒に見て、整理し、残していける場所を目指します。個人が持つファイルを一時的に見せ合うだけでなく、Communityの中で思い出が積み重なっていくアルバムのような体験を大切にします。

Memoriaの設計と実装は、**「Communityは外部には閉じ、内部では開く」「Mediaは博物館の展示物に近い」**という思想を基準に判断します。

## プロダクトの思想

### 現実の集まりに近いCommunity

Communityは、家族やサークルなど、現実世界で一緒に時間を過ごす人たちの集まりに近いものです。外部からは閉じられた空間とし、参加する人たちが安心してMediaを共有できる場所にします。

### 外部には閉じ、内部では開く

CommunityにMediaを公開することは、そのCommunityの参加者に見せることを意味します。参加者全員が等しく閲覧できることを基本とし、一部の参加者だけが閲覧できるMediaや、参加者ごとの細かな閲覧権限は設けません。

「等しく閲覧できる」は閲覧範囲の原則です。Mediaの削除やOriginal downloadなどの操作権限は、参加者の役割やMediaとの関係に応じて定めます。

### Mediaは博物館の展示物に近い

Communityに置かれたMediaは、Uploader個人の手元だけで管理するファイルではなく、その集まりの人たちが一緒に眺め、整理し、残していくものです。誰かがCommunityを離れても、その人が残したCommunity管理Mediaまで自動的に失われることはありません。

この考え方は、Mediaの閲覧体験と継続的な管理に関するものです。著作権や法的所有権の移転を意味しません。

### 個人の場所とCommunityの場所を分ける

Community全員には見せたくないMediaは、個人の領域で管理します。個人管理MediaをCommunityへ共有した場合、そのCommunityの参加者全員が閲覧できますが、Media自体の管理主体は個人のままです。

## 設計原則

| 原則 | 設計・実装で守ること |
| --- | --- |
| Communityの境界を守る | Community外のUserに内部Mediaを公開せず、参加資格に基づいて閲覧を認可する |
| Community内部の閲覧を開く | 共有Mediaは参加者全員が閲覧でき、参加者ごとの閲覧制限を設けない |
| Uploaderと管理主体を分ける | Mediaは1 Userまたは1 CommunityをCustodianとし、Uploaderを別に記録する |
| Communityに残るMediaを守る | Uploaderの退会やAccount削除によってCommunity管理Mediaを自動削除しない |
| 個人のMediaを尊重する | User管理MediaをCommunityへ共有してもCustodyを変更しない |
| 閲覧と管理の権限を分ける | 閲覧範囲が同じでも、削除・Original downloadなどの操作権限は別に定義する |
| 分類と閲覧権限を分ける | GroupやTagはMediaの整理に用い、閲覧範囲やCustodyを変更しない |

Communityへ直接UploadしたMediaはCommunityをCustodianとし、Uploaderは別に記録します。これは管理上、Communityの「共有資産」と説明できる状態ですが、共有資産という言葉はプロダクトの思想ではなく、その思想を実現するための管理モデルを表します。

## 設計・実装判断への適用

新しい機能や仕様を検討するときは、次の観点を確認します。

1. その機能は、現実のCommunityが一緒にMediaを見て残していく体験につながるか。
2. Communityの外部と内部の境界、および参加者全員の閲覧という原則を守っているか。
3. Mediaを誰が管理し、Uploaderや参加者がCommunityを離れた後に何が残るか。
4. 個人のMediaとCommunityのMediaの管理責任を混同していないか。

思想と個別の仕様が衝突する場合は、実装上の例外で解決せず、プロダクトの判断としてレビューします。具体的な操作権限、削除条件、共有解除、データモデルは各Domain設計で定義します。
