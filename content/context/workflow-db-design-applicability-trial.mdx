# DB設計作業への共通テンプレート適用検討（試行）

> これは作業プロセスの共通テンプレートが、設計書間の整合性検証とは異なる「DB設計」にも使えるかを確認した記録です。DBの設計変更・実装・移行は行っていません。

## 対象と参照資料

- 共通実行ルール：`content/context/workflow-execution-rules.mdx` v0.3
- 定義テンプレート：`content/context/workflow-process-template.mdx` v0.2
- DB設計の具体例：`content/media/physical-data-model.mdx`
- 共通DB規約：`content/system/data/physical-model-conventions.mdx`
- 参照ブランチ：`docs/workflow-execution-state-and-coverage`

## 適用できる部分

| テンプレートの項目 | DB設計での具体化例 | 評価 |
| --- | --- | --- |
| 目的と適用範囲 | Mediaのtable、column、constraint、indexの設計 | 適用可能 |
| 開始条件 | 要求、既存schema、関連する正本、対象branchの確定 | 適用可能 |
| 対象と網羅性 | table単位・column単位・FK単位の対象一覧 | 適用可能 |
| 参照情報 | 物理データモデル共通規約、Media設計、実装schema | 適用可能 |
| 作業工程 | 現状確認→変更案→影響確認→承認→設計書更新→検証 | 適用可能 |
| 判断と承認 | schema変更・破壊的移行の判断を人間に確認 | 適用可能 |
| 中断と再開 | 既存schemaが取得できない場合に中断 | 適用可能 |
| 完了条件と証拠 | 設計書の変更差分、規約との照合、必要なCI結果 | 適用可能 |

## 共通テンプレートだけでは決められない事項

- 既存schemaと設計書の差分をどう判定するか。
- column追加・変更、FK、index、migrationの工程順序と検証条件。
- データ移行の安全性、既存データの互換性、rollbackの可否。
- どの変更を承認工程とするか。
- DB設計の完了とDB実装・migration完了をどこで分けるか。

これらは共通テンプレートへ一律に書き込まず、**DB設計用の個別プロセス**で定義するのが妥当です。

## 試行の結論

今回の資料比較では、共通テンプレートの12章構成をDB設計にも割り当てられました。特定の整合性検証だけに依存する項目は見つかりませんでした。ただし、これは定義可能性の机上確認であり、DB設計を実行して工程や完了条件の妥当性を検証した結果ではありません。

次の段階では、DB設計用の個別プロセス案を作成し、実際の小さな設計変更を対象に試行する必要があります。設計変更の対象や承認範囲は別途合意してから決めます。
