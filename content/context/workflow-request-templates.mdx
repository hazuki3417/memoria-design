# 作業プロセスの依頼テンプレート

## 目的

定義済みの作業プロセスを、利用者が自然文で依頼しやすくするための入口です。テンプレートの使用は任意であり、通常の依頼文も受け付けます。各工程・承認・完了条件は対象プロセスと[共通実行ルール](/context/workflow-execution-rules)を正本とし、本書では重複して定義しません。

## 簡易テンプレート

```text
「［プロセス名］」を実行してください。
対象：［リポジトリ・Issue・画面など］
目的：［期待する結果。省略可能］

最新の正本を確認し、定義済みの完了条件まで進めてください。
承認が必要な操作は、実施前に対象と変更案を示して確認してください。
完了せずに回答を終了する場合は、中断・判定不能・承認待ちを明示し、残作業と再開条件を報告してください。
```

## 標準テンプレート

```text
プロセス：［名称または正本へのリンク］
対象：［リポジトリ、Issue、対象範囲］
目的・期待する成果：［達成したい状態］
対象外：［除外する範囲。なければ「指定なし」］
参照基準：［通常は最新develop。必要に応じて指定］
許可する操作：［読み取り・提案・承認済み更新など］
個別承認が必要な操作：［該当する場合に記載。省略しても既存の承認規約を維持］
報告で重視する点：［差異、根拠、未確認事項、次の操作など］

プロセスの開始条件と最新の正本を確認して実行してください。
終了時には作業全体の状態と各工程の結果を区別し、完了・中断・判定不能・承認待ちを明確に報告してください。
```

## 使用例：Issue棚卸し

```text
「Issue棚卸しプロセス」を実行してください。
対象：Memoriaの4リポジトリにあるOpen Issue全件

最新のGitHubと正本を確認し、各Issueの完了条件と証拠を照合してください。
Issue本文の更新やCloseなど、承認が必要な操作は変更案を提示してから確認してください。
作業を途中で停止する場合は中断報告として、完了工程・未完了工程・理由・再開条件を示してください。
```

## 利用上の注意

- 必須情報が不足する場合は、対象プロセスの開始条件に従って確認します。テンプレートの全項目を埋める必要はありません。
- テンプレートに「実行してください」と記載しても、PR作成・マージ、IssueのClose、要求変更などの個別承認は省略されません。
- 中間報告は、同じ依頼の実作業を実際に続ける場合に限ります。回答を終える場合は、実際の終了状態を明示します。
- 新しい作業プロセス自体を定義する場合は[作業プロセス定義テンプレート](/context/workflow-process-template)を使用します。本書は定義用ではなく依頼用です。
