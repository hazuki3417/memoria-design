# 作業プロセスの依頼テンプレート

## 目的

定義済みの作業プロセスを、利用者が依頼しやすくするための入口です。テンプレートの使用は任意で、通常の依頼文も受け付けます。各工程・承認・完了条件の正本は対象プロセスと[共通実行ルール](/context/workflow-execution-rules)です。本書では重複して定義しません。

## 簡易テンプレート

```text
- プロセス：［プロセス名］
- 対象：［リポジトリ・Issue・画面など］
- 目的：［期待する結果。省略可能］
- 依頼：最新の正本を確認し、定義済みの完了条件まで実行する
- 報告：
  - 完了時：作業全体と各工程の結果を区別する
  - 未完了時：中断・判定不能・承認待ちの別、残作業、再開条件を示す
  - 判断が必要な場合：選択肢・推奨案・理由・主な影響を示す
- 承認：個別承認が必要な操作は、実施前に対象と変更案を示して確認する
```

## 標準テンプレート

```text
- プロセス：［名称または正本へのリンク］
- 対象：［リポジトリ・Issue・対象範囲］
- 目的・期待する成果：［達成したい状態］
- 対象外：［除外する範囲。なければ「指定なし」］
- 参照基準：［通常は最新develop。必要に応じて指定］
- 許可する操作：［読み取り・提案・承認済み更新など］
- 個別承認が必要な操作：［該当する場合に記載。省略しても既存の承認規約を維持］
- 報告で重視する点：［差異・根拠・未確認事項・次の操作など］
- 判断支援：［選択肢・推奨案・理由・主な影響］
- 実行条件：
  - 最新の正本とプロセスの開始条件を確認する
  - 定義された工程順・完了条件に従い、完了確認後に次工程へ進む
- 終了時の報告：
  - 作業全体の状態と各工程の結果を分ける
  - 完了・中断・判定不能・承認待ちを明示する
  - 未完了の場合は残作業と再開条件を示す
  - 次の対応と推奨理由を示す
```

## 利用上の注意

- 必須情報が不足する場合は、対象プロセスの開始条件に従って確認します。全項目を埋める必要はありません。
- テンプレートに実行を依頼しても、PR作成・マージ、IssueのClose、要求変更などの個別承認は省略されません。
- 中間報告は、同じ依頼の作業を実際に続ける場合に行います。回答を終える場合は、実際の終了状態を明示します。
- 新しい作業プロセスを定義する場合は[作業プロセス定義テンプレート](/context/workflow-process-template)を使用します。本書は定義用ではなく依頼用です。
