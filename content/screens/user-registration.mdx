# User登録

## 概要

Auth0で認証済みだがMemoria Userとして未登録の利用者が、Memoriaで利用するProfileを確認し、登録を確定する画面です。

> 実装状況: User登録は再実装中です。既存実装の認証時User作成は本仕様の正本とはみなしません。

## 目的

認証済みの未登録Userが、Memoriaで利用するnicknameを確認・必要に応じて変更し、Memoriaへの登録を明示的に確定できるようにします。

## 表示情報

- Memoriaへの登録を完了するための画面であることを利用者が理解できるようにします。
- 登録するUser Profileとしてnicknameを提示します。
- Auth0から表示名を取得できた場合は、その値をnicknameの初期値として提示します。
- Invitation経由であっても、登録成立前にCommunityのMember向け情報を表示しません。Invitation画面で許可されるCommunity情報はCommunityユースケースを正本とします。

## 操作

### 登録を確定する

利用者はnicknameを確認または変更したうえで登録を確定できます。

登録確定時にnicknameが有効であり、認証主体を一意に解決でき、同じissuer・subjectに対応するMemoria Userが存在しない場合にだけMemoria UserをACTIVEで作成します。

入力または登録条件を満たさない場合は登録を開始・完了せず、利用者が修正または再試行できる状態を維持します。

### 登録せずに終了する

利用者はMemoriaへの登録を確定せずに終了できます。「終了」を選択した場合は、nicknameの変更有無にかかわらず確認Dialogを表示します。Dialogには登録を行わずMemoriaとAuth0のsessionを終了して公開側へ戻ることを明示し、「戻る」と「終了」を提示します。前者では入力中のnicknameを保持して登録画面に戻り、後者を確定した場合だけMemoria Userを作成せずにLogoutして公開側へ戻します。

ブラウザを閉じる等の暗黙的な離脱は、この明示的な終了操作とはみなしません。Auth0 sessionが残った状態で再びMemoriaへアクセスし、引き続き未登録である場合はRegistrationへ誘導します。

## 状態

### 登録可能

nicknameを確認・編集し、登録を確定できます。

### 入力不正

nicknameが必須条件を満たさない場合は、問題のある入力と修正方法を利用者が理解できるようにします。登録は実行しません。

### 登録処理中

登録要求を受け付けた後、結果が確定するまで重複した登録確定を防ぎます。処理中であることを利用者へ伝えます。

### 登録失敗

一時的な失敗等、利用者による再試行が可能な場合は、登録が完了していないことを明示し、入力済みnicknameを失わずに再試行できるようにします。

認証主体を一意に解決できない等、同じ入力の再送では解決しない場合は、単純な再試行を促さず、登録できないことを利用者へ伝えます。

### 登録済み

登録要求時点で同じissuer・subjectに対応するMemoria Userがすでに存在する場合は、重複したUserを作成しません。

既存UserがACTIVEで利用可能であることを確認できた場合は登録済みとして扱い、登録成功時と同じNavigation規則で遷移します。DELETING等の利用可能でない状態では登録成功として扱わず、UserユースケースのLogin制約に従って利用を拒否します。

## Navigation

Auth0認証後、issuer・subjectに対応するMemoria Userが存在しない場合にこの画面へ遷移します。

登録開始前に安全な内部復帰先が保持されている場合は、登録完了後にその復帰先へ戻り、元のUser flowを継続します。Invitation URLを起点として認証・登録へ進んだ場合は、この原則に従って許可された元の内部URLへ戻します。

復帰先がない通常のLoginから登録した場合は、登録完了後にApplicationの標準入口へ遷移します。標準入口そのものはこの画面の責務とはせず、Application Navigationの設計で定義します。

登録要求時点ですでに対応するACTIVE Userが存在した場合も、登録成功時と同じ復帰先またはApplicationの標準入口へ遷移します。

利用者が明示的に登録せず終了した場合はLogoutして公開側へ戻ります。ブラウザを閉じる等の暗黙的な離脱では、復帰先や登録状態を変更するための特別な処理を行いません。次回アクセス時に未登録であれば再びこの画面へ誘導します。

Login / Registration前後のreturn destinationと認証後のoperation再開に関する共通behaviorは[Authentication Return / Session Recovery](/design-system/patterns/authentication-return-session-recovery)に従います。

## 制約

- nicknameは必須です。
- nicknameは前後空白を除去した結果が空文字になる値を許可しません。
- nicknameの重複を許可します。
- Auth0から取得した表示名は初期値としてのみ利用し、Memoria nicknameを正本とします。
- Memoria Userは登録確定時にだけACTIVEで作成します。
- 登録前はUpload、Community作成、参加申請を許可しません。
- 同じissuer・subjectに対応するMemoria Userを重複作成しません。
- 認証主体を一意に解決できない場合は登録を拒否します。

## Visual Design（Visual Review方針）

User Profile更新画面と同じフォーム・Field Error・Alert／Notificationのvisual表現を基準とします。登録画面固有の差分は見出し・説明、主Action「登録」、副Action「終了」、および終了確認Dialogです。新規登録では保存済み基準値との差分判定を適用せず、nicknameが有効であれば初期値のまま登録できます。

登録中は重複操作を防ぎ、再試行可能な失敗では入力を保持します。継続不能な問題は一時的なNotificationだけに依存せず、ページ内Alertとして提示します。登録成功後は保持された安全な復帰先または標準入口へ遷移します。画面試作では遷移の代わりに状態を確認できる表示を用意します。

## Responsive対応

表示領域や入力方式が変わっても、nicknameの確認・編集と登録確定というCapabilityは維持します。

現時点では表示領域ごとに異なるInformation、Action、Navigation要件はありません。具体的なlayoutは実装で決定します。
