# 画面仕様

## 概要

このdirectoryはMemoriaの画面単位のUI仕様を管理します。設計書本文・見出し・ページタイトルは日本語を基本とし、Media / Group / Tag / Custodian / GraphQL等のドメイン・技術上の正式名称やコード識別子は必要に応じて英語表記を維持します。Screen Specificationは、画面が満たすべき意味と振る舞いを定義し、具体的なReact / Mantine実装やpixel単位のlayoutは定義しません。

Screen Specificationでは、必要なInformation、Action、State、Navigation上の意味、制約、Responsiveで維持すべきCapabilityを定義します。`Dialog` / `Drawer` / `Modal` / `Page` / `Sidebar` / `split view`等のpresentation、Component構成、配置、寸法、visual designは原則として固定しません。特定のpresentation自体がProduct要件として必要な場合だけ、その理由と要件を明示して例外的に定義します。

UI設計全体の方針は[Frontend UI設計・開発方針](/system/frontend-ui-development)、設計書セットの構成と正本境界は[ドキュメント管理方針](/documentation-policy)、各Screen Specificationの章立て・必須情報・記載粒度は[設計書テンプレート](/design-document-templates#screen-specification)を正本とします。

## 配置

画面ごとに `content/screens/<screen-name>.mdx` を作成します。Nextra上ではProduct domainと利用者のFlowが追いやすい単位でseparatorを設け、同一Flowの画面は実際の確認順に並べます。URLを変える必要がない分類ではflatなfile配置を維持し、各分類が独立した案内や階層を必要とする規模になった場合にsubdirectoryへ移行します。

各Screen Specificationは対応するProduct domainのUse Caseを明示的に参照します。Use Case、domain rule、共通Design System ruleをこのdirectoryへ複製しません。

## 読み取り方

Nextraのサイドメニューは、User、アカウント削除Flow、Community、Media・Groupの順に分類します。複数画面で成立するFlowは概要を先頭に置き、その後へ利用者が確認・操作する順序で各Screen Specificationを並べます。

画面仕様を確認するときは、Related Use CasesからProduct上の目的と制約を確認したうえで、Screen Specificationに記載されたInformation、Actions、States、Navigation、Constraints、Responsive Behaviorを読みます。

StorybookはScreen Specificationを実装したUIを観察・検証するための実行可能なExampleです。Story一覧はこのdirectoryへ複製せず、実装側から対応するScreen Specificationを参照できる関係を基本とします。
