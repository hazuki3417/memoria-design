# User Settings

## 概要

User Settingsは、現在のPersonal / Community contextに依存しないUser本人の設定を扱う画面です。

Application ShellのAccount Menuから到達し、既存のApplication Information Architectureに従ってProfile、Preferences、AccountをSettings配下とし、参照専用のPersonal UsageはSettingsと同階層の独立したdestinationとして扱います。本ページではSettings全体の境界と、Initial Releaseで確定したPreferences / Usageを定義します。

## Information Architecture

Settingsは次の領域をそれぞれ独立したURLを持つpageとして扱います。**User ProfileとSettingsのProfileは同一の画面（`/settings/profile`）です。** 別画面として実装・管理しません。`/settings`へのアクセスは`/settings/profile`へRedirectします。

| 領域 | URL |
| --- | --- |
| Profile | `/settings/profile` |
| Preferences | `/settings/preferences` |
| Account | `/settings/account` |

Settingsは次の領域を持ちます。Personal Usageは `/usage` に独立して配置し、Personal / CommunityいずれのcontextからもAccount Menuを通して到達します。旧 `/settings/usage` のRedirectは提供しません。

- **Profile**: User Profileを確認・変更する。Initial Releaseではnicknameを扱う。詳細は[設定：プロフィール](/screens/user-settings-profile)を正本とする。
- **Preferences**: UserがApplicationの利用体験を調整する設定を扱う。Initial ReleaseではTheme、Personal Accent Color、日付形式、ファイルサイズ単位、Mediaサムネイルサイズ、Media Detailの前後Navigation循環、Media Detailの詳細情報初期表示を提供する。Language / LocaleとTimezoneは将来拡張できる境界を持つが、Initial Releaseでは選択UIを提供しない。
- **Personal Usage（Settings外）**: User本人がCustodianであるPersonal Mediaの利用状況を確認する。Initial Releaseではアカウント用5 GB上限、オリジナルfileのStorage Usage、file format別内訳、登録済みオリジナル件数を提供する。Community管理Mediaの使用量は含めず、各Community contextのUsageから確認する。Uploadの入力制約はMedia Uploadの操作contextで提示する。
- **Account**: account lifecycleに関する操作を扱う。account削除は[Account Deletion Flow](/screens/account-deletion-flow)を正本とする。

SettingsはCommunity管理設定とは分離します。Community contextを利用中でもPersonal contextへ切り替えずAccount Menuから直接到達でき、Settings内の値は現在のCommunityによって変化しません。

Settings内NavigationのHeader / Sidebar / Tabs / Drawer等の具体presentationは固定せず、viewportに応じて適切なComponentを選択します。

## Preferences

### Appearance

Initial ReleaseではTheme、Personal Accent Color、日付形式、ファイルサイズ単位、Mediaサムネイルサイズ、Media Detailの前後Navigation循環、Media Detailの詳細情報初期表示をPreferencesとして提供します。Language / LocaleとTimezoneはApplicationとして扱える境界を持ちますが、Initial ReleaseではUserが変更する設定項目として表示しません。

#### Theme

ApplicationのTheme preferenceとして次の3状態を提供します.

| Preference | Behavior |
| --- | --- |
| System | OS / browserが公開するcolor scheme preferenceに追従する |
| Light | System preferenceに関係なくLight themeを使用する |
| Dark | System preferenceに関係なくDark themeを使用する |

初期値は **System** とします。

System選択中にOS / browserのcolor schemeが変化した場合は、reloadや再選択を要求せずApplicationの実効Themeを追従させます。Light / Darkを明示選択している場合はSystem preferenceの変化でThemeを変更しません。

#### Personal Accent Color

Personal ContextのAccent Colorは、Personalを他のApplication Contextから視覚的に識別するためのUser向けpresentation設定です。

初期値は[Design SystemのColor System](/design-system#color-system)で定めるMemoria EmeraldをSourceとするdefault Accentを使用します。具体的なEmerald paletteとshadeはDesign SystemのVisual Reviewを通して確定します。

UserはColor Pickerから任意の `#RRGGBB` 値へ変更できます。Personal ContextはUserごとに1つのため、Community Accentのようなランダム初期生成や重複回避は行いません。

色を選択した時点で明示的なSave操作を要求せず、即時保存・即時反映します。保存失敗時は最後に確認できている保存済み色へ戻し、再試行可能なFeedbackを提示します。

Personal AccentはLight / Darkで同じ保存済み値をSourceとして扱い、Theme preferenceとは独立して扱います。UIへ適用するResolved ColorはThemeごとのAccessibilityと視認性を保つため[Design SystemのColor System](/design-system#color-system)に従って解決し、shadeやforeground等まで同一であることは要求しません。色だけにContext識別を依存しません。

Personal AccentはUser accountに紐づくpresentation preferenceとしてdevice / browser間で同期します。Themeがbrowser / device-localであることを理由にPersonal Accentをlocal preferenceへ含めません。具体的な永続化・GraphQL契約は[User論理データモデル](/user/data-model)、[User物理データモデル](/user/physical-data-model)、[GraphQL API設計](/system/api/graphql)を正本とします。

### 変更Behavior

Appearanceの選択は明示的なSave操作を要求せず、選択時に即時反映します。

Theme変更によって現在のApplication context、Navigation先、入力中の内容、選択状態等を失わせません。Theme変更はpresentationの変更であり、Domain Actionの再実行やNavigationを発生させません。

AppearanceはPersonal / Communityごとに分けず、同一browser / device上のApplication全体へ適用します。

### 永続化scope

Initial ReleaseのAppearance preferenceは **browser / device-local preference** とします。Memoria User accountへ同期するUser domain dataとして扱いません。

- Themeは同じUserでもbrowser / deviceごとに異なる値を選択できます。
- Themeは同じbrowserでlogout / loginしても、local preferenceが利用可能である限り選択を維持できます。
- Themeを別deviceや別browserへ同期しません。
- Personal Accentを含むaccount同期PreferenceはUser Preferencesとして別device / browserへ同期します。
- Theme preferenceのためだけにUser entity、Profile、GraphQL / APIへ永続化fieldを追加しません。

local preferenceを読み取れない、未保存、または保存値を解釈できない場合はSystemとして扱います。

browser storageの具体方式、SSR / hydration時のTheme適用順序、flash防止等はFrontend implementation contractで決定します。ただし初期表示で不要なTheme切り替わりを可能な範囲で避けることを実装上の品質要件とします。

### 日付形式

日付形式はUser accountに紐づくPreferenceとして保持し、同じUserが利用するdevice / browser間で同期します。任意のformat stringは入力させず、Initial Releaseでは次の3パターンから選択します。

| Preference | 表示例 |
| --- | --- |
| YYYY/MM/DD | 2026/10/05 |
| MM/DD/YYYY | 10/05/2026 |
| DD/MM/YYYY | 05/10/2026 |

初期値は **YYYY/MM/DD** とします。

このPreferenceは日付部分の表示順とseparatorだけを対象とします。Timezoneの選択・変換とは分離し、Initial Releaseでは時刻部分を24時間表記として扱います。12 / 24時間表記の切り替えは日付形式Preferenceへ含めません。

日付形式の変更は他のPreferenceと同様に選択時に即時反映し、明示的なSave操作を要求しません。accountへ保存された値は別device / browserで同じUserが利用する場合にも適用します。

Themeとは永続化scopeが異なります。Appearanceがbrowser / device-localであることを理由に、Preferences全体をlocal storageへ一律に保存しません。日付形式はaccount同期対象として扱い、具体的な永続化・GraphQL契約は[User論理データモデル](/user/data-model)、[User物理データモデル](/user/physical-data-model)、[GraphQL API設計](/system/api/graphql)を正本とします。

### Language / Locale

Applicationは将来の多言語対応を妨げないようLanguage / Localeを独立したPreferenceとして扱える境界を持ちます。ただしInitial Releaseで提供する言語は **日本語のみ** とし、SettingsにはLanguage選択controlを表示しません。選択肢が1つしかない状態で意味のない設定操作をUserへ要求しないためです。

Language / Localeは日付形式、Timezone、ファイルサイズ単位等のPreferenceと同一視しません。将来複数言語を正式に提供するときに、Language選択UI、初期値、fallback、永続化scopeをその時点のProduct requirementに基づいて設計します。

### Timezone

ApplicationはUser-facingな日時をTimezoneへ変換して表示できる境界を持ちます。ただしInitial ReleaseではSettingsにTimezone選択controlを表示せず、実効Timezoneを **Asia/Tokyo** とします。

User-facingな日時表示には原則としてAsia/Tokyoを一貫して適用し、Timezone変換後の日付部分へ日付形式Preferenceを適用します。時刻部分はInitial Releaseでは24時間表記とします。Timezoneはpresentation上の日時解釈を決めるものであり、Domain / APIが保持する日時データそのものを書き換えません。

将来Timezone選択を提供する場合は、System / 明示指定Timezone等の選択方法とaccount同期を含むPreferenceとして改めて有効化します。具体的な永続化・GraphQL契約は[User論理データモデル](/user/data-model)、[User物理データモデル](/user/physical-data-model)、[GraphQL API設計](/system/api/graphql)を正本とします。

### ファイルサイズ単位

ファイルサイズ単位はUser accountに紐づくPreferenceとして保持し、同じUserが利用するdevice / browser間で同期します。

Initial Releaseでは次の2つの単位体系から選択します。

| Preference | 単位 | 基数 |
| --- | --- | --- |
| Decimal | KB / MB / GB | 1 KB = 1000 bytes |
| Binary | KiB / MiB / GiB | 1 KiB = 1024 bytes |

初期値は **Decimal** とします。Binaryを選択した場合は1024基準の値に `KB` / `MB` / `GB` を使用せず、`KiB` / `MiB` / `GiB` として単位体系を明示します。

このPreferenceはMedia DetailのOriginal file size、Usage等、Application内でUserへ提示するfile size表示へ一貫して適用します。Domain dataやStorage上のsizeそのものを書き換える設定ではなく、保持しているbyte数等の正本から表示値を導出するpresentation preferenceとして扱います。

変更は選択時に即時反映し、明示的なSave操作を要求しません。accountへ保存された値は別device / browserで同じUserが利用する場合にも適用します。

具体的な永続化・GraphQL契約は[User論理データモデル](/user/data-model)、[User物理データモデル](/user/physical-data-model)、[GraphQL API設計](/system/api/graphql)を正本とします。

### Mediaサムネイルサイズ

Media Collectionで表示するサムネイルサイズはUser accountに紐づく共通Preferenceとして保持し、同じUserが利用するdevice / browser間で同期します。Media Browserだけでなく、Group Browser内のaggregate Media等、Media CollectionとしてMediaを一覧表示する箇所へ一貫して適用します。

Initial Releaseでは **小 / 中 / 大** の3段階を提供し、初期値は **中** とします。

| Preference | 意図 |
| --- | --- |
| 小 | 一覧性を優先し、一度により多くのMediaを確認しやすくする |
| 中 | 一覧性と個々のMediaの確認しやすさを両立する |
| 大 | 個々のMediaのvisual contentをより確認しやすくする |

このPreferenceは固定pixel値や固定grid列数をUser preferenceとして定義するものではありません。Responsive viewport classificationとは独立して扱い、各viewportで適切な実寸・列数へ適応しながら、同一viewport内では小 < 中 < 大の相対的なサムネイルサイズ関係を維持します。

具体的なthumbnail寸法、spacing、grid layoutはUI具体化とVisual Reviewで決定します。Preferenceとしてraw pixel値を保存・公開しません。

このPreferenceはMedia Collectionの閲覧密度を調整するものであり、Media Detailのメイン画像、Upload preview、選択control内の補助thumbnail等、Collection閲覧を目的としないMedia表示には適用しません。Initial ReleaseではCollectionごとの個別設定を持たず、1つの共通Preferenceを使用します。将来、Collectionごとに異なるサイズを必要とするProduct needが確認された場合は、共通Preferenceをdefaultとして個別overrideする方式を検討します。

変更は選択時に即時反映し、明示的なSave操作を要求しません。accountへ保存された値は別device / browserで同じUserが利用する場合にも適用します。具体的な永続化・GraphQL契約は[User論理データモデル](/user/data-model)、[User物理データモデル](/user/physical-data-model)、[GraphQL API設計](/system/api/graphql)を正本とします。

### Media Detailの前後Navigation循環

Media Detailの前後NavigationをCollectionの境界で循環させるかはUser accountに紐づくPreferenceとして保持し、device / browser間で同期します。

Initial Releaseでは **OFF** を初期値とします。OFFでは利用元Collectionの先頭・末尾をNavigationの境界とします。ONでは末尾から「次へ」で先頭へ、先頭から「前へ」で末尾へ移動します。

循環を有効にしても、Detailを開いた利用元Collectionのfilter条件と順序は変更しません。未取得のMediaが存在する場合もclient上で読み込み済みの範囲をCollection全体の境界として扱わず、必要に応じてConnectionを追加取得して実際の先頭・末尾を解決します。

Collectionが1件だけの場合は、同じMedia自身への前後移動Actionを成立させません。

変更は選択時に即時反映します。具体的な永続化・GraphQL契約は[User論理データモデル](/user/data-model)、[User物理データモデル](/user/physical-data-model)、[GraphQL API設計](/system/api/graphql)を正本とします。

### Media Detailの詳細情報初期表示

Media Detailを開いたときの詳細情報領域の初期状態はUser accountに紐づくPreferenceとして保持し、device / browser間で同期します。Responsive領域ごとの利用可能な表示領域が異なるため、WideとMediumを個別に設定します。

| 対象 | Preference | 初期値 |
| --- | --- | --- |
| Wide | 詳細情報を展開して開く | ON |
| Medium | 詳細情報を展開して開く | OFF |
| Compact | Preference対象外 | Compact固有のResponsive Behaviorに従う |

このPreferenceはMedia Detailを新しく開いた瞬間の初期状態だけを決定します。Detailを開いた後にUserが詳細情報を展開・折りたたみしても、その操作からPreferenceを自動更新しません。

Wide / Mediumのviewport classificationに応じて対応するPreferenceを解決し、Detail UIには解決後の初期状態を渡します。各表示箇所でPreference値を個別に分岐させません。CompactではこのPreferenceを参照せず、Compact向けのProgressive Disclosureを使用します。

Detailを開いたままviewportが変化した場合は、breakpointを跨ぐたびにPreferenceを再適用してUserの操作状態を強制的にリセットしません。Responsive layoutへ適応しつつ、現在の状態を維持可能な範囲で維持します。CompactではCompact固有のpresentationを優先します。

変更は選択時に即時反映し、次にMedia Detailを開くときの初期状態から使用します。具体的な永続化・GraphQL契約は[User論理データモデル](/user/data-model)、[User物理データモデル](/user/physical-data-model)、[GraphQL API設計](/system/api/graphql)を正本とします。

## Usage

### Scope

Personal Usage（`/usage`）は現在のUser accountがCustodianであるPersonal Mediaの利用状況だけを表示します。Community管理MediaやCommunityの使用量は含めません。Personal MediaをCommunityへ共有してもCustodianはUserのままのため、そのOriginalはPersonal Usageだけに計上します。Communityへ直接Uploadされ、CommunityがCustodianとなったOriginalはCommunity Usageだけに計上します。

Community Usageは現在のCommunity contextに属する別destinationです。具体的な表示・Navigationは[Community Usage](/screens/community-usage)を正本とします。

### Storage Usage

Personal accountのStorage上限は **5 GB**（5,000,000,000 bytes）です。これは各User accountに個別適用され、Communityの上限と連動しません。各Communityには別途5 GBの独立した上限を適用します。現時点の設計値は5 GBとし、画面上では現在適用中の上限、使用量、残容量または使用率を提示します。

容量・件数に算入するのは、Media登録が確定したOriginal fileだけです。表示用Variant等の派生file、処理中間データ、未登録・未確定のUploadは含めません。Media登録後に派生fileのProcessingが失敗しても、登録済みOriginalは使用量・件数に含みます。

容量表示はPreferencesのファイルサイズ単位に従います。Initial Releaseの初期設定はDecimalのため、通常はGB表記です。Binaryを選択した場合は同じbyte数をMiB / GiB等で表示し、上限の実体は5,000,000,000 bytesのままです。

### File format別内訳

使用量と登録件数の両方を、利用者が意味を理解しやすいOriginalのformat単位で表示します。

| 表示分類 | 含める拡張子 |
| --- | --- |
| JPEG | .jpg、.jpeg |
| PNG | .png |
| WebP | .webp |
| HEIC / HEIF | .heic、.heif |

同じformatの別名拡張子は統合します。JPEGの.jpgと.jpegは一つのJPEG行に、.heicと.heifは一つのHEIC / HEIF行に集計します。format分類はfile extensionやClient申告MIMEではなく、Originalの実内容を検証して確定したcanonical formatを正本とします。表中の拡張子は利用者向けの表示例です。各行には登録済みOriginalの件数とOriginal byte数から導出した使用量を表示します。総件数・総使用量はformat別内訳の合計と一致します。

内訳はMediaの業務分類や操作対象ではなく、Personal Storage Usageの説明情報です。ここからMediaをformat別に一括削除・変換するActionは提供しません。

### Upload制約の扱い

Personal Usage（`/usage`）に1回のUpload可能件数、1 fileあたりの最大size、対応formatの操作制約一覧を常設しません。これらはMedia Uploadの操作contextで提示し、具体的なUpload条件は[Media Upload](/screens/media-upload)と[Media処理と派生物](/media/processing)に従います。

Upload後に登録が確定したOriginalは、Personal accountまたはCommunityそれぞれのUsageへ反映します。Upload画面での容量超過時の挙動は[Media Upload](/screens/media-upload)に従います。

## Accessibility / Design System

Light / Darkの双方でDesign Systemのsemantic color roleを維持し、個別ScreenがThemeごとの固定色をProduct meaningとして直接持たないことを基本とします。

Themeによって情報、Action、状態表現、focus indicator等のCapabilityを変えません。色だけに意味を依存せず、双方のThemeでWCAG 2.2 AAを満たすことを目標とします。

System / Light / Darkの選択状態は、色の見た目だけでなくcontrolの選択状態として認識可能にします。

## Account

Initial ReleaseのAccount領域では、User account lifecycleに関する操作として **account削除のみ** を提供します。削除の具体的なUser Flowは[Account Deletion Flow](/screens/account-deletion-flow)を正本とします。

認証情報の正本はAuth0であり、password変更等の認証情報管理をMemoria独自のAccount設定として重複提供しません。認証方法の確認、session / device管理、外部account連携等はInitial ReleaseのSettingsへ追加せず、具体的なProduct needが確認された場合にAuth0との責務境界を含めて設計します。

## Initial Release対象外

- User accountを介したAppearance preferenceのdevice間同期
- Community / Personal contextごとのTheme
- Communityごとのbrand theme
- Theme全体の配色をUserが任意色へ変更するcustom theme（Personal / Community Context Accentは対象外）
- font family、font size、density等の追加Appearance preference
- Theme変更によってProduct Capabilityやauthorizationを変えること

将来User preferenceを追加する場合も、account同期が必要かdevice-localであるべきかを設定ごとに判断し、Preferences全体を一律に同じ永続化scopeへ固定しません。

## Visual Prototype / Reviewで確認する事項

- Settings navigationがWide / Compact双方で現在位置を理解できること
- System / Light / Darkの選択状態と即時反映が明確であること
- Light / Dark双方で主要Screen、Dialog、feedback、focus stateのcontrastとsemantic roleが維持されること
- Theme切り替え時にlayout shift、入力消失、Navigation stateの消失が発生しないこと

## Settings NavigationとURL state

Settingsの現在sectionはURLを正本とし、Screen Component内部にURLと独立した選択section stateを保持しません。

- `/settings/profile` はProfileを表示します。
- `/settings/preferences` はPreferencesを表示します。
- `/settings/account` はAccountを表示します。
- `/settings` は `/settings/profile` へRedirectします。

Settings NavigationにUsageを含めません。Personal UsageはAccount Menuから開く独立画面とし、Personal / Communityいずれのcontextからも `/usage` に遷移します。旧 `/settings/usage` へのRedirectは設けません。

WideのSettings side navigationとCompactのsection selectorは、route変更後にURLへ対応するsection内容と選択状態を表示します。Browserの戻る・進む、reload、deep linkでもURLから同じsectionを復元します。

SettingsはApplication contextから独立したUser本人のdestinationですが、認証後Applicationの一部として共通Application Shell内に表示します。Settings各sectionやAccount Deletion Flowが個別にShellを重複所有しません。

Account領域の「アカウントを削除する」は `/settings/account/delete` へのNavigationとして扱います。
