# User Settings

## 概要・責務

User Settingsは、現在のPersonal / Community Contextに依存しないUser本人の設定領域です。Account Menuからアクセスし、Profile、Account、Preferences、Usageをそれぞれ独立したURLの画面として扱います。

本書はSettings全体のInformation Architecture、NavigationとContext上の境界を正本とします。各画面の情報・操作・保存・失敗時の扱いは個別Screen Specification、採用済みの配置・操作感・Responsiveは対応UI Designを参照します。

## Information Architecture

Settingsは次の領域をそれぞれ独立したURLを持つpageとして扱います。**User ProfileとSettingsのProfileは同一の画面（`/settings/profile`）です。** 別画面として実装・管理しません。`/settings`へのアクセスは`/settings/profile`へRedirectします。

| 領域 | URL |
| --- | --- |
| Profile | `/settings/profile` |
| Account | `/settings/account` |
| Preferences | `/settings/preferences` |
| Usage | `/settings/usage` |

SettingsのNavigationは「プロフィール → アカウント → 環境設定 → 利用状況」の順とし、本人情報・アカウント管理をまとめた後に利用環境・利用量を配置します。Wideの左サイドメニューとCompactの画面選択で同じ順序を使用します。

Settingsは次の領域を持ちます。

- **Profile**: User Profileを確認・変更する。Initial Releaseではnicknameを扱う。詳細は[設定：プロフィール](/screens/user-settings-profile)を正本とする。
- **Preferences**: [設定：環境設定](/screens/user-settings-preferences)に定義する、ThemeとUser Preferencesの変更を扱う。
- **Usage**: User本人がCustodianであるPersonal Mediaの利用状況を確認する。詳細は[Usage：画面詳細仕様](/screens/usage)と[画面UI設計](/screens/usage-ui-design)を参照し、Community Usageとは集計scopeを分離する。
- **Account**: [設定：アカウント](/screens/user-settings-account)からaccount削除フローへ進む。削除の成立条件・Flowは[Account Deletion Flow](/screens/account-deletion-flow)を正本とする。

SettingsはCommunity管理設定とは分離します。Community contextを利用中でもPersonal contextへ切り替えずAccount Menuから直接到達でき、Settings内の値は現在のCommunityによって変化しません。

Settingsの採用済みNavigation表示は[共通UI設計](/screens/user-settings-ui-design)を正本とします。

## NavigationとURL state


Settingsの現在sectionはURLを正本とし、Screen Component内部にURLと独立した選択section stateを保持しません。

- `/settings/profile` はProfileを表示します。
- `/settings/preferences` はPreferencesを表示します。
- `/settings/usage` はUsageを表示します。
- `/settings/account` はAccountを表示します。
- `/settings` は `/settings/profile` へRedirectします。

WideのSettings side navigationとCompactのsection selectorは、route変更後にURLへ対応するsection内容と選択状態を表示します。採用された配置とInteractionは[共通UI設計](/screens/user-settings-ui-design)を参照します。Browserの戻る・進む、reload、deep linkでもURLから同じsectionを復元します。

SettingsはApplication contextから独立したUser本人のdestinationですが、認証後Applicationの一部として共通Application Shell内に表示します。Settings各sectionやAccount Deletion Flowが個別にShellを重複所有しません。

Account領域の「アカウントを削除する」は `/settings/account/delete` へのNavigationとして扱います。

## 画面間の共通保証

- Settings全体はApplication Shell内で扱い、SectionごとのShellを重複しません。
- Light / Darkいずれも情報・操作・Focus・Feedbackを維持し、色だけで意味を伝えないことを基本とします。Accessibilityの横断規則は[Design System](/design-system)に従います。
- Section切替は編集・削除などの業務Actionを自動で実行しません。未保存のProfile編集の破棄やPreferencesの自動保存はそれぞれのScreen Specificationに従います。
