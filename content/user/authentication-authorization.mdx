# Userの認証と認可

## 概要

> 実装状況: Auth0認証とUser関連実装は存在しますが、本ページで定義する登録・削除・整合性は未実装です。

Auth0とMemoriaの責務、認証主体の解決、token検証、権限評価、再認証、復帰先を定義します。

## 主体と責務

| 情報・処理 | 正本 |
| --- | --- |
| password、外部identity、認証session | Auth0 |
| issuer・subjectと内部Userの対応 | Memoria |
| nickname、User状態 | Memoria |
| Membership、Administrator、Media権限 | 各Memoria domain |

## 取得する認証情報

Auth0からはissuer、subjectと登録画面のnickname初期値に使う表示名だけを利用します。emailとprofile画像は要求・保存せず、issuer・subjectを画面や通常logへ出力しません。

## 認証主体の解決

issuerとsubjectの組は1件のUserにだけ対応します。同じemailや表示名を根拠に統合しません。一致するUserがない場合は登録画面へ遷移し、複数件に一致する不整合は認証失敗として運用対応します。

## token検証と権限評価

APIはtokenの署名、issuer、audience、有効期限を検証します。権限はtokenへ固定せず、操作時のUser状態、Membership、Administrator、Custodyから評価します。

## 再認証

account削除の最終確定前はAuth0再認証を必須とします。失敗・取消し・期限切れの場合は削除Jobを開始せず、MediaとCommunityの個別確認も省略しません。

## session失効と復帰先

session失効時は再Loginし、User状態と現在の権限を再評価します。Login・登録後の復帰先はallowlistに一致する内部相対URLだけを受け付けます。

## エラーと境界条件

| 状況 | 扱い |
| --- | --- |
| 期限切れ・不正なtoken | 認証を拒否する |
| issuer・subjectに一致するUserなし | 登録画面へ案内する |
| DELETING User | Loginと操作を拒否する |
| account削除時の再認証失敗 | 削除Jobを開始しない |
| 外部URLへの復帰要求 | 拒否する |
