# Userレコードパターン

## 概要

> 実装状況: Auth0認証とUser関連実装は存在しますが、本ページで定義する登録・削除・整合性は未実装です。

User登録、account削除受付、cleanup完了時のrecord変化と保持対象を定義します。

## Userを登録する

Auth0認証済みでも登録未確定ならusers行はありません。登録確定時にU1をACTIVEで作成します。

| table | key | 主な値 |
| --- | --- | --- |
| users | U1 | issuer=I1、subject=S1、nickname=家族A、status=ACTIVE |
| user_preferences | U1 | account同期Preferenceの初期値 |

## account削除Reviewと再認証

Final Review時にACTIVEなReview R1を作成します。この時点ではU1はACTIVEのままで、削除Jobは作成しません。

| table | key | 主な値 |
| --- | --- | --- |
| account_deletion_reviews | R1 | user_id=U1、status=ACTIVE、plan_snapshot=検証済み計画 |

Auth0強制再認証が成功するとR1へbindingしたrecordを作成します。

| table | key | 主な値 |
| --- | --- | --- |
| account_deletion_reauthentications | R1 | user_id=U1、expires_at=成立から10分、consumed_at=NULL |

計画を変更して新しいReview R2を作成する場合、R1をINVALIDATEDとして旧bindingを流用しません。

## account削除を受け付ける

最終確定時にU1・R1・再認証bindingを再検証し、同じTransactionでR1をCONSUMED、bindingを消費済みにしてU1をDELETINGへ更新し、D1を作成します。

| table | key | 主な値 |
| --- | --- | --- |
| users | U1 | status=DELETING |
| user_deletion_jobs | D1 | user_id=U1、status=PENDING、target_snapshot=確定対象 |

以後のLoginと全操作を拒否し、対象Media・Communityを非表示・変更不可にします。

## cleanupを完了する

User管理Media、Variant、共有、関連を削除し、保持するCommunity管理Mediaのuploaded_by_user_idをNULLにします。Membershipと未処理申請を解除・無効化し、選択されたCommunityとMediaを削除します。Auth0のMemoria account削除後、usersとJobを物理削除します。

途中失敗時は完了済みstepを再実行しても結果が変わらないようにし、UserとJobを保持して運用上再開します。

## 禁止・境界パターン

- 登録未確定の認証主体にUser recordを作成しない。
- issuer・subjectが同じUserを重複登録しない。
- 同じUserに複数のACTIVE Reviewを作成しない。
- Review変更後に旧Review / reauthentication bindingを再利用しない。
- 同じUserに複数の有効な削除Jobを作成しない。
- DELETING Userの権限や削除対象を追加しない。

## 非影響範囲

削除対象に含めないCommunity、他UserのMedia、外部provider accountは変更しません。保持するCommunity管理MediaはUploader参照だけをNULLにします。
