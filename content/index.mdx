# Memoria

Memoriaは、家族や部活動などのクローズドなCommunityで生まれる静止画像・動画と、その付加情報を管理・共有・継承するためのプロダクトです。Word、PDF、記事などを扱う汎用ストレージサービスは対象としません。

このサイトは、4つの実装リポジトリに共通するプロダクト設計とアーキテクチャの正本です。設計書は静止画像と動画を扱うMediaを基準とし、実装との差分は各ページの概要直下に記載します。

プロダクトの存在意義、信念、設計・実装判断の指針は[プロダクトビジョン・設計原則](/product-vision)を参照してください。

## 初めて読む場合

プロダクトの概要から詳細へ理解する場合は、次の順序で読みます。

1. [プロダクトビジョン・設計原則](/product-vision)で存在意義と判断基準を確認する
2. [初回Releaseの範囲と成功条件](/first-release)で直近のGoal、対象機能、対象外を確認する
3. [ユビキタス言語](/ubiquitous)で主要なProduct用語を確認する
4. [Mediaドメイン](/media)、[Communityドメイン](/community)、[Userドメイン](/user)で主要概念と責務境界を確認する
5. 各domainのユースケースで利用者の目的と操作を確認する
6. UIを確認する場合は[画面仕様](/screens)でProduct domainとFlowごとのScreen Specificationを確認する
7. [システム全体構成](/system)と[Application Information Architecture](/system/application-information-architecture)でシステムとApplicationの全体像を確認する
8. 必要に応じて各domainの詳細設計とWeb / API / Data / Infrastructure / 横断設計へ進む
9. 開発する場合は[ローカル開発環境](/local-development)と[ブランチ運用](/branch-strategy)を確認する

## リポジトリ

- `memoria-web`: Web UIとGraphQLクライアント
- `memoria-api`: GraphQL API、ドメインロジック、永続化
- `memoria-design`: プロダクト設計と横断的な意思決定
- `memoria-IaC`: AWS CDKによる実行環境

設計書はこのリポジトリへ集約します。実行可能なschema、設定、セットアップ、検証コマンドは、それを所有する実装リポジトリを正本とします。
