# Memoria

Memoriaは、家族や部活動などのクローズドなCommunityで生まれる静止画像・動画と、その付加情報を管理・共有・継承するためのプロダクトです。Word、PDF、記事などを扱う汎用ストレージサービスは対象としません。

このサイトは、4つの実装リポジトリに共通するプロダクト設計とアーキテクチャの正本です。設計書は静止画像と動画を扱うMediaを基準とし、実装との差分は各ページの概要直下に記載します。

## 初めて読む場合

プロダクトの概要から詳細へ理解する場合は、次の順序で読みます。

1. [初回Releaseの範囲と成功条件](/first-release)で直近のGoal、対象機能、対象外を確認する
2. [Mediaドメイン](/media)と[Communityドメイン](/community)でProductの主要概念と責務境界を確認する
3. [Mediaユースケース](/media/use-cases)と[Communityユースケース](/community/use-cases)で利用者の操作を確認する
4. [ユビキタス言語](/ubiquitous)で用語の意味を確認する
5. [リポジトリ構成](/system)でシステム全体と責務境界を確認する
6. 各domainの論理モデル、物理モデル、レコードパターン、Transaction、設計判断へ進む
7. 開発する場合は[ローカル開発環境](/local-development)と[ブランチ運用](/branch-strategy)を確認する

## リポジトリ

- `memoria-web`: Web UIとGraphQLクライアント
- `memoria-api`: GraphQL API、ドメインロジック、永続化
- `memoria-design`: プロダクト設計と横断的な意思決定
- `memoria-IaC`: AWS CDKによる実行環境

設計書はこのリポジトリへ集約します。実行可能なschema、設定、セットアップ、検証コマンドは、それを所有する実装リポジトリを正本とします。
